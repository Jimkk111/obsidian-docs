# 分包与性能优化

## 分包加载

小程序有体积硬约束：**所有分包合计不超过 30M，主包（含 tab 页/默认启动页）单个不超过 2M**（以官方最新文档为准）。业务变大必须拆分包：

```json
{
  "pages": ["pages/index/index"],            // 主包：启动页 + tab 页
  "subpackages": [
    {
      "root": "packageOrder",
      "pages": ["pages/submit/index", "pages/success/index"]
    },
    {
      "root": "packageAddress",
      "pages": ["pages/list/index", "pages/edit/index"]
    }
  ],
  "preloadRule": {                            // 分包预下载：进首页时预拉订单包
    "pages/index/index": {
      "network": "all",
      "packages": ["packageOrder"]
    }
  }
}
```

- 原则：**主包只放启动必需与 tab 页**，功能域拆成独立分包，按需下载。
- **独立分包**（`"independent": true`）：不依赖主包可独立运行——分享直达、扫码进入时无需下载主包，启动最快；但里面**不能用主包的组件/JS/插件**（app.wxss 也不生效）。
- **分包异步化**：分包可以引用主包的自定义组件/JS（`"componentPlaceholder"` 兜底），反向不行。

## 启动性能

启动 = 冷启动下载代码包 → 注入逻辑层 → 初始渲染。官方优化清单按收益排序：

1. **控制代码包体积**：拆分包、清理死代码与无用资源（图片是重灾区）、压缩混淆。
2. **按需注入**：`app.json` 配 `"lazyCodeLoading": "requiredComponents"`，只注入当前页需要的代码，不配就全量注入。
3. **首屏体验**：骨架屏（工具可自动生成）、初始渲染缓存（`"initialRenderingCache": "static"` 把首屏 WXML 快照缓存到本地）、关键请求提前（App onLaunch 里并行发起首屏数据）。
4. 合理使用**分包预下载**消除跳转白屏。

## 运行时性能

### setData（最高频的优化点）

- 批量合并：多次修改合成一次 setData；对高频变化（滚动、计时）节流。
- 路径更新大数组：`this.setData({'list[3].checked': true})` 而不是整组替换。
- 非渲染数据用 `pureDataPattern` 纯数据字段或干脆放 this 上。
- `onPageScroll`/`onMouseMove` 等高频回调里禁止 setData。

### 长列表

- 万级数据用**虚拟列表**：官方 recycle-view（扩展库）或自己实现占位高度 + 可视区渲染。
- 图片：列表图 `mode="widthFix"` + `lazy-load` + 合理尺寸（不要 2000px 原图当缩略图）、webp。

### 渲染层细节

- `wx:if` vs `hidden` 的取舍（见视图层笔记）。
- `wx:key` 必给且稳定（别用 index 当 key 配合会变化的列表）。
- 避免过深节点层级与超大页面 WXML（渲染层是 WebView，节点数直接吃内存）。

## 体验层优化

- 骨架屏/加载态先行，请求失败有兜底页与重试入口。
- `wx.showLoading` 与页面内骨架配合使用，防止"白屏焦虑"。
- 弱网：请求超时设短 + 失败重试 + `onNetworkStatusChange` 全局断网监听跳提示页。

## 审核与发布链路

开发版（开发者工具/真机预览）→ 上传 → 体验版（扫码内测，最多 15 个体验成员）→ 提交审核 → 全量/分阶段发布（灰度）。提审前过一遍类目合规与隐私协议（`__usePrivacyCheck__`、隐私弹窗 API `wx.requirePrivacyAuthorize`）。

## 经验提示

- "启动白屏长"九成是主包太大：先看代码包分析（工具-代码依赖分析），再谈其他。
- 性能问题排查顺序：setData 调用频率/体积 → 代码包体积 → 请求数与首屏串行 → 节点数。工具的 Performance/Audits 面板能直接给数据。
