# 双线程架构与项目结构

## 双线程模型（小程序与 Web 最本质的差异）

小程序由**两个线程**协作运行：

| 线程  | 运行内容                         | 所在环境                                    |
| --- | ---------------------------- | --------------------------------------- |
| 逻辑层 | 所有 JS 代码（App/Page/Component） | JSCore（iOS）/ V8（Android），**没有 DOM/BOM** |
| 渲染层 | WXML/WXSS 编译后的界面             | WebView，每个页面一个独立 WebView                |

两线程通过微信客户端（Native 层）桥接通信，**数据从逻辑层到渲染层要经过序列化传输**（`setData` 的本质）。由此推出三条核心推论：

1. **没有 `window`、`document`**，一切 DOM 操作不存在，必须数据驱动视图。
2. **`setData` 是性能命门**：每次调用都要序列化传给渲染层，频繁调用 / 传大对象 / 传不需要渲染的数据都是反模式。
3. `wx.getSystemInfoSync()` 等 API 替代浏览器探测；`setTimeout/setInterval` 等纯 JS 能力照常可用。

> Skyline 渲染引擎（基础库 2.29+ 可选）改用自研渲染后端 + 单线程简化模型，弱化了双线程开销，是官方主推的新一代方案；老项目默认仍是 WebView 渲染。

## 项目结构

```
miniprogram/
├── app.js               # 应用入口逻辑 App()，全局生命周期
├── app.json             # 全局配置：页面注册、窗口、tabBar、分包
├── app.wxss             # 全局样式
├── project.config.json  # 开发者工具/项目配置：appid、基础库版本
├── sitemap.json         # 收录配置
├── pages/               # 页面（每个页面一个目录）
│   └── index/
│       ├── index.wxml   # 结构（类似 HTML）
│       ├── index.wxss   # 页面样式（默认只作用于本页）
│       ├── index.js     # 页面逻辑 Page({})
│       └── index.json   # 页面级配置（覆盖 app.json 的 window）
├── components/          # 自定义组件 Component({})
└── utils/               # 工具模块（CommonJS require / ES Module import 均支持）
```

要点：

- **页面必须先在 `app.json` 的 `pages` 数组注册**才能访问，数组第一项为启动页。
- 页面四个文件同名同目录；`index.json`/`index.wxss` 可省略。
- 模块化：默认 CommonJS（`module.exports` / `require`），也支持 ES Module，项目里二选一保持统一。

## app.json 关键配置

```json
{
  "pages": ["pages/index/index", "pages/order/index"],
  "window": {
    "navigationBarTitleText": "餐掌柜",
    "navigationBarBackgroundColor": "#E95F3C",
    "navigationBarTextStyle": "white",
    "enablePullDownRefresh": false,
    "onReachBottomDistance": 50
  },
  "tabBar": {
    "list": [
      { "pagePath": "pages/index/index", "text": "首页" },
      { "pagePath": "pages/my/my", "text": "我的" }
    ]
  },
  "lazyCodeLoading": "requiredComponents",
  "style": "v2"
}
```

- `window` 配置原生导航栏颜色/标题、下拉刷新开关、触底距离——**导航栏是系统组件，不是你写的 HTML**。
- `tabBar` 最少 2 个、最多 5 个，pagePath 必须在 pages 中；tab 页只能用 `wx.switchTab` 跳转。
- `lazyCodeLoading: "requiredComponents"` 是启动性能优化的标配项（按需注入代码）。

## 运行与调试环境

- 微信开发者工具：模拟器 + Chrome DevTools 风格调试器（Sources/Network/AppData/WXML 面板），AppData 面板可直接看改 data。
- 真机调试：真机运行 + 电脑端 devtools 联调；预览版（二维码）/体验版（上传后设为体验版）/正式版（提审发布）三条发布链路。
- 域名白名单：`wx.request` 的域名必须在小程序后台配置为**合法域名（HTTPS + ICP 备案）**，开发时可在工具里勾选"不校验合法域名"绕过。

## 经验提示

- 每个页面独立 WebView 意味着**页面数据不共享**，跨页通信靠：路由 query、页面栈 `getCurrentPages()`、全局 store、事件通道 EventChannel、storage。
- 双线程下"频繁 setData 小块数据"优于"一次 setData 大对象"；纯展示中间态用纯数据字段（`pureDataPattern`）避免无谓传输。
