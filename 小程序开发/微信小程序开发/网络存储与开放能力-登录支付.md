# 网络存储与开放能力：登录/支付

## 网络请求

```js
wx.request({
  url: 'https://api.example.com/user/login',  // 必须已在后台配置合法域名，必须 HTTPS
  method: 'POST',
  data: { code: 'js_code_xxx' },
  header: { 'content-type': 'application/json' },
  timeout: 10000,
  success: (res) => { /* res.statusCode / res.data */ },
  fail: (err) => {},
  complete: () => {},
})
```

- 小程序**没有浏览器同源策略**，但有自己的约束：合法域名白名单（HTTPS + 备案）、并发上限 10 个（request）、默认超时 60s（建议显式设短）。
- 没有拦截器机制，**必须自封装**：统一拼 baseUrl、注入登录态、统一错误提示、401 跳登录。这是所有小程序项目的标配手写题：

```js
function request(options) {
  return new Promise((resolve, reject) => {
    wx.request({
      ...options,
      url: BASE_URL + options.url,
      header: { ...options.header, Authorization: getToken() },
      success: (res) => {
        if (res.statusCode === 401) return handleExpired()
        res.data.code === 0 ? resolve(res.data) : reject(res.data)
      },
      fail: reject,
    })
  })
}
```

- 其他：`wx.uploadFile`/`wx.downloadFile`（FormData 上传、进度回调）、`wx.connectSocket`（WebSocket，全双工、需 wss 域名白名单）、`wx.downloadFile` 产物配合 `wx.openDocument` 预览。

## 存储

```js
wx.setStorageSync('sessionId', 'abc')   // 同步 API，会阻塞
wx.getStorageSync('sessionId')
wx.removeStorageSync('sessionId')
wx.clearStorageSync()
// 异步版 wx.setStorage({ key, data, success })
```

- 上限：**单个 key 1MB，总量 10MB**；本质是持久化的 KV 文件存储。
- 与 localStorage 的差异：同步 API 为主、无事件机制、无法被其他页面监听变化。
- 定位：存登录态、主题等**小而关键**的数据；业务数据（购物车等）以后端为准，本地只做缓存。

## 登录：wx.login → code → 后端换 session

标准时序（面试必考，官方推荐流程）：

```
1. wx.login()                          → 临时凭证 code（5 分钟有效，一次性）
2. code 传给自己后端
3. 后端调 auth.code2Session            （appid + secret + code）
   → openid（用户唯一标识）+ session_key（会话密钥）
4. 后端生成自定义登录态（如 token/JSESSIONID）返回前端
5. 前端存 storage，后续请求头携带
```

关键认知：**openid 永远不该出现在前端**；`session_key` 是解密敏感数据用的，同样只在服务端。code 不是用户信息，只是换 openid 的凭证。

### 获取用户信息的现代化（2022 后）

- `wx.getUserInfo` / `uni.getUserProfile` **已废弃**，只会返回灰色头像和"微信用户"。
- 现行方案是**头像昵称填写能力**：

```html
<button open-type="chooseAvatar" bind:chooseavatar="onChooseAvatar">
  <image src="{{ avatarUrl }}" />
</button>
<input type="nickname" placeholder="请输入昵称" />
```

  用户点头像选微信头像、输入框键盘上方一键填微信昵称——数据由用户主动确认，合规且真实。
- 手机号：`<button open-type="getPhoneNumber" bindgetphonenumber="...">` 拿到 `code`，**后端**调 phonenumber.getUserPhoneNumber 换手机号；需**企业认证**小程序，个人主体不可用。
- 其他授权：`wx.authorize({scope})` 预授权（相册、位置等），拒绝后引导 `wx.openSetting`。

## 支付：wx.requestPayment

```
1. 前端把订单提交给商户后端
2. 后端调微信"统一下单/JSAPI下单" API → prepay_id
3. 后端用商户密钥对参数二次签名，返回五元组：
   timeStamp / nonceStr / package(=prepay_id=xxx) / signType / paySign
4. 前端 wx.requestPayment(五元组) → 唤起支付面板
5. 支付结果以后端回调（payment notify）为准，前端 success 只是体验层
```

- 前端职责只有第 1、3、4 步——**签名一律在后端**；个人主体无法发起真实支付（需企业资质 + 商户号），这是学习项目里"支付做不了"的根因。
- 支付结果必须以后端收到微信回调为准；前端 success 回调里做的事要幂等。

## 其他常用开放能力

- 分享：页面定义 `onShareAppMessage`（好友）/`onShareTimeline`（朋友圈）；`<button open-type="share">` 主动触发。
- 订阅消息：`wx.requestSubscribeMessage({tmplIds})` 一次性订阅，后端用模板 id 推送。
- 客服消息：`<button open-type="contact">`。
- 二维码：`wx.scanCode` 扫码（堂食扫码点餐入口）；小程序码由后端生成。

## 经验提示

- 请求封装里 401 的处理：清本地登录态 → reLaunch 到登录/首页 → 重新 wx.login 静默登录，用户无感知（wx.login 不需要用户授权弹窗）。
- WebSocket 要封装重连 + 心跳，小程序切后台 5s 后连接会被断开，回前台 onShow 时主动重连。
