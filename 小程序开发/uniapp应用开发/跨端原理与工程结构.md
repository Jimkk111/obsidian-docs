# 跨端原理与工程结构

## uni-app 是什么

基于 Vue 的跨端框架：**一套 Vue 代码编译到 iOS/Android App、H5、微信/支付宝/抖音等各家小程序**。与"React Native/Taro"同属跨端赛道；对有 Vue 背景的开发者，它是写小程序时迁移成本最低的方案。

## 跨端原理：编译器 + 运行时

```
源代码（Vue SFC + uni 组件 + uni API）
        │  编译器（编译期：标签转换、指令转换、API 前缀替换）
        ▼
各端产物：微信小程序（wxml/wxss/js）/ H5（完整 SPA）/ App（vue 或 nvue 渲染）
        │  运行时（各端实现 @dcloudio/uni-xxx 运行层）
        ▼
统一行为：生命周期、路由、请求、存储在各端语义一致
```

两层理解：

1. **编译层**：`<view>` 在 H5 端编译为 div、小程序端就是 view；`uni.request` 在 H5 端映射到 XHR、小程序端映射到 wx.request。你写的永远是 uni 规范。
2. **运行层**：逻辑层统一用你写的 Vue 代码跑；视图层各端用各自最优渲染（小程序 WebView、App 可选 weex 原生）。

因此能直接复用 Vue 生态（Pinia/Vuex、vue 组合式 API），但**不能直接用依赖 DOM/BOM 的库**（axios、jQuery、多数图表库要用 uni 生态版本或适配层）。

## 两种工程形态

| 形态 | 创建方式 | 依赖管理 | 适用 |
|---|---|---|---|
| **HBuilderX 工程** | HBuilderX 新建项目 | 编译器内置，无 package.json | 快速上手、课程项目（本仓库即此形态） |
| **CLI 工程** | `npx degit dcloudio/uni-preset-vue#vite-ts` | npm/pnpm，Node 18+ | 团队工程化、CI/CD、想用完整 npm 生态 |

Vue 版本由 `manifest.json` 的 `"vueVersion": "2" | "3"` 决定；Vue3 走 Vite 编译链（新项目一律选 Vue3）。

## 目录结构（HBuilderX 工程）

```
project/
├── main.js            # 入口：Vue3 用 createSSRApp 创建并返回 { app, Pinia }
├── App.vue            # 根组件：无 template（Vue3 明确禁止），只有生命周期 + 全局样式
├── manifest.json      # 应用配置：appid、vueVersion、各端专项配置
├── pages.json         # ★ 核心：页面注册 + 窗口样式 + tabBar + easycom + 分包
├── uni.scss           # 全局 SCSS 变量（编译期注入所有组件）
├── pages/             # 页面目录
├── components/        # 自定义组件（配合 easycom 自动注册）
├── static/            # 静态资源（不参与编译，直接拷贝）
├── store/  或 stores/ # Vuex/Pinia
└── unpackage/         # 编译产物（各端一份，git 忽略，不要手改）
```

### main.js（Vue3 标准写法）

```js
import { createSSRApp } from 'vue'
import App from './App.vue'
import * as Pinia from 'pinia'

export function createApp() {
  const app = createSSRApp(App)
  app.use(Pinia.createPinia())
  return { app, Pinia }   // uni-app 特殊约定：必须把 Pinia 一起返回
}
```

注意是 `createSSRApp` 而非 `createApp`——uni-app 编译链的要求，背下来即可。

### pages.json

```json
{
  "pages": [
    { "path": "pages/index/index", "style": { "navigationBarTitleText": "首页" } }
  ],
  "globalStyle": {
    "navigationBarTitleText": "瑞吉外送",
    "navigationBarBackgroundColor": "#E95F3C"
  },
  "tabBar": { "list": [{ "pagePath": "pages/index/index", "text": "首页" }] },
  "easycom": {
    "autoscan": true,
    "custom": { "^uni-(.*)": "@/components/uni-$1/uni-$1.vue" }
  }
}
```

语义与小程序 app.json 基本对齐（多了 easycom、condition 启动参数等），是读任何 uni-app 项目的第一站。

### manifest.json

- 微信端：`mp-weixin.appid`（要真机预览必须填，可用测试号）。
- `"vueVersion": "3"`。
- H5 端：`h5.router`（hash/history 模式）、devServer 代理。
- App 端：模块权限（地图/支付/推送）按需勾选。

## 编译产物与调试

- HBuilderX 运行到"微信开发者工具"：先在工具-设置里开启服务端口；产物在 `unpackage/dist/dev/mp-weixin`。
- 运行到浏览器（H5 端）调试最方便；小程序端行为差异（登录、支付、授权）必须真机/工具验证。
- H5 端跑在浏览器里才有 DOM（条件编译下可见），**写代码时永远按"无 DOM"标准**，才能保证跨端。

## 经验提示

- HBuilderX 工程没有 node_modules，想用 npm 包（如 pinia）在 Vue3 工程下直接 import 即可，编译器会处理；复杂依赖建议转 CLI 工程。
- `unpackage/` 要进 `.gitignore`；项目初始没有 git 就先 `git init`（教训：旧项目整份拷贝目录当备份，就是没有版本管理的标志）。
- 编译报错先看是哪一端：条件编译写漏端、Vue3 下用了 Vue2 独有写法（$on、filters）是大头。
