### 2026-09-06 CommonForm 落地实现与踩坑（苍穹外卖 Vue3 重构）

**背景**：7 个表单页手写 n-form，校验器大量重复（价格校验写了两遍）。按"form-item-list 配置驱动 + modelValue"思路封装 CommonForm.vue 并全量接入（登录、改密码、员工、分类、菜品、套餐、拒单/取消原因）。

**设计决策**：
- **职责正交**：表单只管"渲染控件 + 双向绑定 + 校验"，不内置查询请求。搜索栏 = CommonForm + 按钮 + DataTable，三者拼装。
- **插槽逃生口**：每个字段 key 同时是具名插槽，配置表达不了的复杂内容（菜品口味配置、图片上传、套餐内嵌表格）原样保留手写实现，不硬塞配置。
- **required 自动生成规则**：trigger 按控件类型区分（select/radio/date 用 change，其余 blur），`item.rule` 可追加覆盖。
- **不内置按钮**：actions 插槽由调用方决定放"查询"还是"保存/取消"。

**好处**：表单页样板骤减；校验器收口到一处；规则生成/校验/重置行为全局统一。

**踩坑与解决**：

1. **defineModel 的 prop 名**：`defineModel()` 默认 prop 名是 `modelValue`，父组件 `:model="ruleForm"` 传不进去。要显式指定：`defineModel('model', { required: true })`。
2. **父组件 reactive 对象不要用 v-model 传**：`v-model="ruleForm"`（const reactive）会编译成对常量的赋值。直接 `:model="ruleForm"` 传对象引用，组件内写属性即可（defineModel 的 ref 指向的就是父组件对象）。
3. **vue/no-mutating-props**：直接改 props 深层属性会被 lint 报。defineModel 返回的 ref 不属于 props 引用，绕开了该规则。
4. **script setup 不能 export**（连 interface 都不行，TS1184）：`FormItemOption` 等类型挪到独立 `types/form.ts`。
5. **搜索时机**：params 深度监听直连输入框 v-model 会每敲一个键查一次。页面维护两个状态：输入框绑定草稿值，点查询/回车时才写入正式 params 触发重查。
6. **编辑器保存编码**：文件曾被编辑器按 GBK 重编码导致中文注释全部乱码，组件文件统一 UTF-8 保存。

**关键代码**（model 收口与规则生成）：

```vue
<script setup lang="ts">
const model = defineModel<Record<string, unknown>>('model', { required: true })
const getText = (key: string) => (model.value[key] ?? null) as string | null
const setField = (key: string, v: unknown) => { model.value[key] = v }

const rules = computed(() => {
  const result: Record<string, FormItemRule[]> = {}
  for (const item of props.items) {
    const list = item.rule ? (Array.isArray(item.rule) ? [...item.rule] : [item.rule]) : []
    if (item.required && !list.some((r) => r.required)) {
      list.unshift({ required: true, message: `${item.label}不能为空`, trigger: 'blur' })
    }
    if (list.length) result[item.key] = list
  }
  return result
})
defineExpose({ validate, restoreValidation })
</script>
```
