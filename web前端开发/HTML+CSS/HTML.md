## 一、HTML 基础

### 1. 文档结构与骨架

任何一个 HTML 文档都以文档类型声明开头。`<!DOCTYPE html>` 的作用是告诉浏览器"这份文档按照 HTML 标准来解析"。在 HTML5 之前的年代，声明需要引用一份冗长的 DTD（文档类型定义），而 HTML5 把它简化成了这一句。虽然它看起来只是一个形式，但绝不能省略：浏览器根据有无 DOCTYPE 来决定使用**标准模式**还是**怪异模式**（quirks mode）渲染页面。在怪异模式下，盒模型的计算方式、行内元素的尺寸行为等都与标准不同，CSS 会表现得"莫名其妙"，所以现代页面必须始终保留这一行。

声明之后是根元素 `<html>`，它包裹了整个文档。`<html>` 上通常设置 `lang` 属性来声明页面的主语言，例如 `<html lang="zh-CN">`。这个属性不是摆设：屏幕阅读器会根据它选择正确的语音发音，浏览器会据此提示翻译，搜索引擎也会把它作为语言信号。根元素内部只包含两个子元素：`<head>` 和 `<body>`。`<head>` 中放的是**元数据**，即"关于文档的信息"，它们不会直接显示在页面上；`<body>` 中放的是用户能在浏览器里看到、与之交互的所有内容。

一个完整的 HTML5 骨架如下：

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>页面标题</title>
  </head>
  <body></body>
</html>
```

### 2. head 与元数据

`<head>` 里最重要的几个元素是 `title`、`meta`、`link`、`style` 和 `script`。

`<title>` 定义文档标题，显示在浏览器标签页上。它同时是搜索结果中那条蓝色链接的文字来源，也是用户收藏页面时的默认名称，因此应该写成概括页面内容的完整短语，而不是简单堆砌关键词。

`<meta>` 是元数据的"万能容器"，根据 `name` / `http-equiv` / `charset` 等属性的不同承担不同职责。`<meta charset="UTF-8">` 声明文档的字符编码，它必须出现在 `head` 的前部，因为浏览器解析到它之前都是按猜的编码读字节，放得太靠后容易出现中文乱码。`<meta name="viewport">` 控制移动端视口，是移动端适配的前提，详细原理见 [[#八、HTML 常见面试问题]]。SEO 相关的元数据主要有 `<meta name="description" content="页面描述">`，搜索引擎通常会把这段描述展示在搜索结果的摘要里；曾经流行的 `keywords` 如今已经被主流搜索引擎忽略。此外还有针对社交平台分享卡片的 Open Graph 协议（`og:title`、`og:image` 等），决定链接被分享到微信、Twitter 等平台时显示的标题和缩略图。

`<link>` 用于引用外部资源，最常见的用法是引入外部样式表 `<link rel="stylesheet" href="style.css">`，以及声明网站图标 `<link rel="icon" href="favicon.ico">`。它还能做性能优化：`<link rel="preload">` 提前加载关键资源，`<link rel="dns-prefetch">` / `<link rel="preconnect">` 提前完成 DNS 解析和连接建立。`<style>` 则是把 CSS 直接写在文档内部的内嵌样式表。

`<script>` 是 head 中最值得注意的元素，因为它的加载和执行方式直接影响页面性能。默认情况下，浏览器解析 HTML 遇到 `<script src="...">` 时会**停下来**，先下载脚本、执行完毕，再继续解析后面的 HTML——因为脚本可能修改 DOM。对于放在 head 里的脚本，这种阻塞意味着用户会长时间面对白屏。为此 HTML 提供了两个属性：`defer` 让脚本与 HTML 解析**并行下载**，但要等 DOM 完全解析完成后才按顺序执行，并且执行时机早于 `DOMContentLoaded` 事件，适合需要操作 DOM 的业务脚本；`async` 同样并行下载，但下载完立即执行，不保证多个脚本之间的顺序，适合相互独立的脚本（如统计埋点）。简单记忆：**defer 保顺序、等 DOM；async 不保序、下完就跑**。head 中还可以放 `<noscript>`，为禁用了 JavaScript 的环境提供降级提示。

### 3. 元素、属性与语法

HTML 文档由元素（element）组成，元素由开始标签、内容和结束标签构成，元素之间可以嵌套。嵌套要遵守语法和语义上的规则：块级元素可以包含行内元素和其他块级元素，但 `<p>` 内部不允许出现 `<div>`、`<h1>` 等块级元素——浏览器遇到这种情况会自动提前闭合 `<p>`，产生与源码不符的 DOM 结构；同理，`<a>` 里面不要再嵌套 `<a>`。浏览器对错误写法有很强的容错能力，"能显示"不代表"写得对"，错误的嵌套会导致样式和脚本行为难以预测。

有一类元素叫**空元素**（void elements），它们本身就不该有内容，因此没有结束标签，例如 `<br>`、`<hr>`、`<img>`、`<input>`、`<meta>`、`<link>`、`<source>`、`<col>`。给空元素写结束标签（如 `<img></img>`）是错误的。与之相关的是**布尔属性**，这类属性"存在即生效"，不需要赋值，例如 `<input disabled>` 表示禁用、`<option selected>` 表示默认选中。按照规范可以只写属性名，效果等同于把值设为属性名本身或空字符串。

有些字符在 HTML 中有特殊含义，不能直接写在文本里：小于号 `<` 是标签的开始、`&` 是实体引用的开始。这时要用**HTML 实体引用**（character reference）来表示它们，常见的有 `&lt;`（<）、`&gt;`（>）、`&amp;`（&）、`&quot;`（"）、`&nbsp;`（不换行空格）、`&copy;`（©）。最后，注释写作 `<!-- 注释内容 -->`，注释不能嵌套。

## 二、文本内容

### 1. 标题与段落

标题使用 `<h1>` 到 `<h6>` 六个元素，数字越大层级越低。使用标题时有三条重要的原则。第一，每个页面只用一个 `<h1>`，它代表页面的主题，其余章节用 h2、h3 逐级细分。第二，**不要跳级**，h2 之后应该接 h3 而不是直接跳到 h4，否则屏幕阅读器的用户会误以为遗漏了内容。第三，标题只用来表达内容的层级结构，不能因为"想要字小一点"就去用低级标题——控制外观是 CSS 的职责。搜索引擎也依赖标题层级来理解页面的内容权重，这是 SEO 的基础信号之一。

`<p>` 表示一个自然段，是块级元素。`<br>` 强制文本换行，但它只应该用在**换行本身有意义**的场合，比如诗歌的分行、邮寄地址的分段；用连续多个 `<br>` 来制造段间距是滥用，段落之间本来就该用 `<p>` 分隔，间距交给 CSS 的 margin。`<hr>` 表示"话题的转换"，比如文章中从一个章节切换到另一个不相关的章节，它渲染成一条水平线，但语义重点是分隔而不是画线。

### 2. 文本级语义

HTML5 的核心理念之一是"语义优先于样式"：如果一个标签同时有语义和默认样式，应该选语义标签，外观交给 CSS 调整。

表示"重要"和"强调"的两个基本标签是 `<strong>` 和 `<em>`。`<strong>` 表示内容很重要，默认加粗；`<em>` 表示语气上的强调，默认倾斜。它们分别取代了纯样式的 `<b>` 和 `<i>`，因为屏幕阅读器会用不同的语气朗读它们，搜索引擎也能从中获取权重信息，而 `<b>`、`<i>` 只是"把字变粗/斜"，没有传达任何含义。

`<mark>` 表示与当前上下文相关、需要高亮的文本，典型场景是搜索结果页里高亮命中关键词。代码相关的一对标签是 `<code>`（行内代码）和 `<pre>`（预格式化文本，保留源码中的空格和换行），二者通常嵌套使用：`<pre><code>const a = 1;</code></pre>`，pre 负责保留格式，code 负责标记"这是代码"。

`<time>` 用机器可读的格式标记时间，例如 `<time datetime="2026-09-08">今天</time>`，标签内的文字给人看，`datetime` 属性给机器看，浏览器扩展、日历工具可以据此解析。`<sub>` 和 `<sup>` 分别是下标和上标，用于化学式（H₂O）和脚注编号。`<abbr>` 标记缩写词，通过 `title` 属性提供全称，鼠标悬停时会显示提示。最后，`<small>` 用于附注类的小字，如版权声明、法律条款；`<del>` 和 `<ins>` 分别表示文档修订中被删除和插入的内容，默认样式为删除线和下划线，比直接划掉文字更能表达"修订历史"的含义。

### 3. 列表

无序列表 `<ul>` 与有序列表 `<ol>` 内部都只能直接放列表项 `<li>`。两者的选择标准是**列表项之间是否有顺序**：操作步骤、排名用 `<ol>`，功能入口、材料清单用 `<ul>`。`<ol>` 还有三个实用的属性：`start` 指定起始编号（比如从 10 开始编号）、`reversed` 让编号倒序、`type` 切换编号样式（数字、字母、罗马数字）。

列表可以嵌套，但子列表必须整个放在外层 `<li>` 内部，放在 `<ul>` 直接子级是非法的。第三种是描述列表 `<dl>`，它由术语 `<dt>` 和描述 `<dd>` 成对组成，适合术语表、商品参数、问答对这类"名值对"内容。一个术语也可以对应多个描述。

### 4. 引用与联系信息

`<blockquote>` 用于块级的长引用，整段引用他人的话，`cite` 属性可以提供来源 URL（但不会显示，仅供机器读取）。`<q>` 用于行内的短引用，浏览器会自动为它加引号，因此源码里不要再手动写引号，否则会出现双重引号。容易混淆的是 `<cite>`：它引用的不是"某句话"，而是**作品的名称**，比如书名、文章名、电影名，默认显示为斜体。

`<address>` 表示当前文档或当前文章作者的联系信息，通常是页面或文章页脚的邮箱、地址、社交账号，默认显示为斜体。注意它不是通用的"地址"标签，快递收货地址这类内容不应该用它。

## 三、超链接

### 1. a 元素与链接

`<a>` 是 HTML 的灵魂，正是超链接把一个个网页连成了"网"。链接的目标由 `href` 属性指定，可以是绝对 URL（`https://...`）、相对路径（相对于当前文档的路径），也可以是特殊协议：`mailto:user@example.com` 唤起邮件客户端，`tel:+8613800000000` 唤起拨号，在移动端很有用。

**相对路径与绝对路径**的选择需要理解 URL 解析规则：`./` 表示当前目录，`../` 表示上一级目录，以 `/` 开头的路径从站点根目录出发。相对路径便于项目整体迁移，根路径在目录层级较深时更不容易写错。

**文档片段（锚点）**用于页内跳转。给目标元素设置 `id`，然后 `href="#id值"` 即可跳转到该位置；`href="#"` 或 `href="#top"` 会回到页面顶部。页内锚点跳转后 URL 会带上片段标识符，刷新页面仍停留在该位置。

`target` 属性决定在哪里打开链接：默认 `_self` 在当前页打开；`_blank` 在新标签页打开。这里有一个重要的安全细节——用 `target="_blank"` 打开的新页面可以通过 `window.opener` 拿到原页面的引用并对其进行操控（称为反向标签钓鱼），所以**外链新开页面时应同时写 `rel="noopener noreferrer"`**，切断 opener 关系并屏蔽 referrer。`rel` 属性的其他常用值还有 `nofollow`，它告诉搜索引擎"不要追踪此链接、不要传递权重"，常用于广告链接和用户生成的内容。

`download="文件名"` 属性让浏览器**下载**资源而不是导航过去，可以指定保存时的文件名。注意它只对同源 URL 生效，跨域资源会忽略该属性。最后，链接文字本身要有意义：屏幕阅读器用户常会"抽取所有链接"来浏览页面，一整页的"点击这里"会让他们完全无法分辨目标，搜索引擎也依赖链接文字理解目标页面的主题。

## 四、图片与多媒体

### 1. 图片 img

`<img>` 通过 `src` 指定图片地址，通过 `alt` 提供替代文本。`alt` 是可访问性的核心：图片加载失败时会显示 alt 文字，屏幕阅读器会朗读它，搜索引擎靠它理解图片内容。写 alt 的原则是描述图片传达的**信息**而非图片本身，"图表显示 2026 年销量增长 30%"好过"柱状图"；而纯装饰性的图片必须写成 `alt=""`（空字符串），这样屏幕阅读器会直接跳过它，避免朗读出无意义的文件名。**省略 alt 属性**和写空 alt 是两回事，省略会让屏幕阅读器把图片路径读出来。

显式设置 `width` 和 `height` 属性是现代开发的好习惯：浏览器在图片下载完成前就能算出宽高比、预留出空间，避免图片加载后把下面的内容突然推下去，这种抖动就是性能指标里的**累积布局偏移（CLS）**。即使在 CSS 里用 `width: 100%; height: auto` 覆盖，HTML 属性依然有价值，因为浏览器可以从中推导宽高比。

`loading="lazy"` 开启原生懒加载，图片滚动到接近视口时才开始下载，能显著减少首屏请求数；但首屏的大图（如 banner）不要加，否则反而延迟了关键内容的显示。格式选型上，照片用 JPEG，需要透明背景用 PNG，动图用 GIF，图标和几何图形用 SVG（矢量，无限缩放不失真），追求体积则优先 WebP / AVIF 这类现代格式，它们在同等画质下比 JPEG 小 25% 以上。

### 2. 响应式图片

响应式图片解决两个问题：**分辨率切换**和**艺术指导**。

分辨率切换是"同一张图的不同大小版本"：小屏幕没必要加载 1600px 的大图。做法是用 `srcset` 列出候选图片及其固有宽度（单位 `w`），再用 `sizes` 告诉浏览器这张图实际会以多宽显示（可以写媒体查询条件），浏览器根据视口宽度和设备像素比自动选择最合适的一张下载：

```html
<img
  src="img-800.jpg"
  srcset="img-400.jpg 400w, img-800.jpg 800w, img-1600.jpg 1600w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="示例" />
```

艺术指导针对的是"不同屏幕应该看到**不同的裁剪**"：宽屏横图在手机上应该换成竖构图。这时用 `<picture>` 元素，内部放若干 `<source>`（用 `media` 或 `type` 声明条件）加一个兜底的 `<img>`，浏览器从上到下匹配第一个满足条件的 source：

```html
<picture>
  <source media="(max-width: 600px)" srcset="img-mobile.jpg" />
  <source type="image/webp" srcset="img.webp" />
  <img src="img.jpg" alt="示例" />
</picture>
```

`<picture>` 也常用来做格式降级：优先给 WebP，不支持的浏览器回退到 JPEG。而单纯的分辨率切换用 `srcset` 就够了，不必动用 `<picture>`。

### 3. audio 与 video

`<audio>` 和 `<video>` 是 HTML5 取代 Flash 的多媒体方案，标签内部可以写降级文字给不支持的浏览器。常用属性有：`controls` 显示浏览器自带的播放控件；`autoplay` 自动播放——但现代浏览器出于体验限制**只允许静音的自动播放**，所以 `autoplay` 必须配合 `muted` 才会生效；`loop` 循环播放；`muted` 静音；`preload` 控制预加载策略（`none` 不预载、`metadata` 只载元信息、`auto` 尽量预载）。`<video>` 独有的 `poster` 指定播放前显示的封面图。

一个媒体标签内可以写多个 `<source>`，浏览器按顺序采用第一个自己支持的格式，这样就用一套代码兼容了 MP4 和 WebM 等不同容器。字幕用 `<track>` 子元素提供，`kind="subtitles"` 声明类型、`srclang` 声明语言、`src` 指向 WebVTT 格式（.vtt）的字幕文件，可以同时提供多语种让用户选择。

### 4. 嵌入其他技术

`<iframe>` 在页面内开辟一个**独立的浏览上下文**，嵌入另一个完整文档。它常用于嵌第三方内容（地图、视频、广告）。理解 iframe 的关键是它与父页面相互隔离：内部文档有自己的 window 和 document，父页面无法直接访问其内部 DOM（受同源策略约束），CSS 也不会穿透进去。安全方面，`sandbox` 属性以白名单方式限制被嵌页面的能力（是否允许脚本、表单、弹窗等），嵌入不可信内容时应尽量收紧；`loading="lazy"` 让视口外的 iframe 延迟加载。父页面向 iframe 通信靠 `postMessage`。

`<embed>` 和 `<object>` 是更古老的嵌入方式，如今主要用于浏览器原生渲染 PDF 等内容，`<object>` 允许在标签体内写降级内容，比 `<embed>` 略灵活。

`<canvas>` 是一块位图画布，本身"什么都没有"，所有内容靠 JavaScript 通过 Canvas API（或 WebGL）逐像素绘制，适合游戏、图表、图像处理等高频重绘场景；它的内容只是像素，缩放会失真，也不可访问。`<svg>` 则是内联的矢量图形，是 DOM 的一部分：可以无限缩放不失真，能用 CSS 控制样式、用 JS 操作节点，适合图标、logo、数据可视化。简单说：**静态可交互的图形用 svg，像素级高频重绘的用 canvas**。

## 五、表格

### 1. 表格结构与合并单元格

表格由 `<table>` 包裹，基本单元是行 `<tr>`，行内放单元格——表头单元格 `<th>` 和数据单元格 `<td>`。`<th>` 默认加粗居中，并应设置 `scope="col"` 或 `scope="row"` 声明它到底是"这一列的表头"还是"这一行的表头"，屏幕阅读器依赖 scope 在朗读数据时自动报出对应的行列标题。

较复杂的表格应该用语义分区元素组织：`<thead>` 包住表头行、`<tbody>` 包住数据行、`<tfoot>` 包住汇总行。这样书写不仅结构清晰，浏览器在长表格分页打印时也能每页重复表头。`<caption>` 给整个表格加标题，必须写成 `<table>` 的第一个子元素。这三个分区加 caption 对屏幕阅读器至关重要，是"表格只用于表格数据、绝不用来布局"这条老规矩的另一半原因——布局表格对读屏用户是灾难。

合并单元格用两个属性：`colspan="2"` 让一个单元格横跨两列，`rowspan="2"` 让它纵跨两行。合并之后，被"吃掉"的那几个格子必须从源码里删掉，否则该行会多出单元格，表格错位。

当需要按**列**统一设置样式时，逐个给 td 加类很麻烦，用 `<colgroup>` 配合 `<col>` 可以按列声明：

```html
<table>
  <colgroup>
    <col />
    <col span="2" style="background: #f5f5f5" />
  </colgroup>
  <tr>
    <th>姓名</th><th>语文</th><th>数学</th>
  </tr>
</table>
```

## 六、表单与控件

### 1. form 元素

`<form>` 定义一个表单区域，决定数据**提交给谁、怎么提交**。`action` 指定提交的服务器地址，不写则提交到当前页面；`method` 指定 HTTP 方法，`get` 会把数据拼接在 URL 的查询字符串上，有长度限制、会被浏览器缓存和收藏，适合搜索、筛选这类"取数据"的操作；`post` 把数据放在请求体里，容量大也不暴露在地址栏，适合登录、注册、文件上传这类"改数据"的操作。

`enctype` 指定数据的编码类型，只在 `post` 时有意义：默认值 `application/x-www-form-urlencoded` 处理普通键值对；**上传文件必须用 `multipart/form-data`**，它会把文件内容作为独立部分编码；`text/plain` 几乎只在调试时用。

理解**表单提交过程**很重要：用户点击提交按钮后，浏览器先执行客户端校验，通过后遍历表单内所有控件，把**每一个拥有 name 属性且未禁用**的控件收集成 `name=value` 对（同名多值如一组复选框会有多对），按 method 和 enctype 编码后发送到 action。由此推出两个常见坑：控件忘了写 `name` 就永远不会被提交；`disabled` 的控件值不会提交，而 `readonly` 的会。另外，一个页面可以有多个独立的 form，但 form 之间不能嵌套，表单控件若想作用于某个 form 又不写在它内部，可以用 `form` 属性关联。

### 2. input 类型与常用属性

`<input>` 是表单的主力控件，完全靠 `type` 属性变形。常用的类型有：`text`（单行文本）、`password`（密码，遮蔽显示）、`email`（自带格式校验，移动端弹出邮箱键盘）、`number`（配 `min` / `max` / `step` 约束数值范围）、`checkbox`（复选框）与 `radio`（单选框，**name 相同的才是同一组**，靠 name 实现互斥）、`file`（文件选择，配 `multiple` 可多选、`accept` 限定可选类型）、`date` / `time` / `datetime-local`（原生日期时间选择器）、`color`（取色器）、`range`（滑块）、`search`（搜索框）、`hidden`（隐藏域，不显示但值随表单提交，用来携带不需要用户看见的数据）、`submit` / `reset` / `button`（按钮类）。

通用属性方面：`placeholder` 是输入前的灰色提示文字，它**不能代替 label**——输入开始后就消失了，屏幕阅读器也未必朗读；`required` 标记必填；`pattern` 用正则表达式约束格式；`minlength` / `maxlength` 限制长度；`checked` 设置默认选中。特别要分清 `disabled` 和 `readonly`：disabled 表示控件被禁用，不可聚焦、不可编辑、**值不随表单提交**；readonly 表示只读，不可编辑但值会提交。`autocomplete` 让浏览器提供历史输入补全，`autofocus` 让页面加载后自动聚焦。

选对 type 的价值在于"免费的校验和体验"：`type="email"` 会在提交时自动校验邮箱格式，移动端会弹出带 @ 的键盘——这些不需要写一行 JS。

### 3. 其他表单控件

`<select>` 是下拉选择框，内部用 `<option>` 提供选项、`<optgroup>` 给选项分组加标签。常用属性：`selected` 设置默认选中项，`multiple` 开启多选，`size` 设置可见行数。`<textarea>` 是多行文本框，用 `rows` / `cols` 控制默认大小，是否可拖拽调整由 CSS 的 `resize` 决定；注意它的**初始值写在标签内容里**而不是 value 属性，这点和 input 不同。

`<datalist>` 为文本输入提供候选建议：给 `<datalist>` 设置 id 并在其中写 `<option>`，再让 `<input list="该id">` 关联。与 `<select>` 的区别是 datalist 只是"建议"，用户仍可自由输入，适合既有常用值又允许自定义的场景。

`<button>` 与 `<input type="submit">` 的区别有两个层面。表现上，button 可以包含 HTML 内容（图标加文字、加粗排版），input 按钮只能显示纯文本。更关键的是**默认行为**：button 在 form 内的默认 `type` 是 `submit`！所以"点击做个弹窗"的按钮必须显式写 `<button type="button">`，否则在表单里一点击就把表单提交了——这是非常经典的 bug 来源。button 的 type 可取 `submit`（默认）、`reset`（重置表单）、`button`（纯按钮，无默认行为）。

### 4. label 与可访问性

`<label>` 为控件提供文字说明，点击 label 等同于点击控件本身，既扩大了点击热区（对复选框、单选框这类小控件尤其友好），又是屏幕阅读器朗读控件名称的首要来源——**没有正确关联的表单控件在读屏用户面前等于没有名字**。

label 与控件有两种关联方式。显式关联是给控件设置 `id`，label 用 `for="该id"` 指向它，这是推荐写法，label 和控件在 DOM 里可以分开摆放；隐式关联是直接把控件包在 label 内部，不需要 for 和 id。两种方式选其一即可。若某控件确实不适合展示可见 label（如搜索框），至少要用 `aria-label` 提供可访问名称。

### 5. 客户端表单校验

HTML5 内置了约束校验（constraint validation），校验依据是控件上的约束属性：`required`（必填）、`type`（email/url 等格式）、`pattern`（正则）、`min` / `max` / `step`（数值范围）、`minlength` / `maxlength`。用户提交表单时浏览器自动检查，任一控件不通过就**阻止提交**并弹出提示气泡。配合的 CSS 伪类可以实时反映状态：`:valid` / `:invalid` 标记校验通过与失败，`:required` / `:optional` 区分必填与非必填，`:placeholder-shown` 识别"还没输入"的控件（常用来避免一进页面所有 input 都标红的问题）。

如果内置的提示气泡不满足需求，可以用**约束校验 API** 自定义校验逻辑：`element.checkValidity()` 返回布尔值表示是否通过；`element.reportValidity()` 执行校验并展示提示；`element.validity` 是状态对象，包含 `valueMissing`（必填未填）、`typeMismatch`（类型不符）、`patternMismatch`（正则不符）、`tooShort` / `tooLong` 等布尔字段，可用于精确定位错误原因；`element.setCustomValidity("错误信息")` 用于设置自定义校验结果——传入非空字符串表示校验失败并显示该信息，传空字符串表示通过，复杂的业务校验（如"用户名已被占用"）就靠它接入。

用 `<form novalidate>` 可以整体关闭内置校验，改为完全由 JS 接管交互。最后必须强调：客户端校验只是**体验优化**，用户完全可以绕过浏览器直接发请求，服务端必须对同一套规则再做一次校验，这才是安全的底线。

## 七、文档结构与语义化

### 1. 页面结构标签

HTML5 引入了一批**区块元素**（sectioning elements），让"页面骨架"可以脱离无意义的 div 嵌套来表达。一个典型的页面结构如下：

```html
<body>
  <header>
    <h1>站点名称</h1>
    <nav>主导航</nav>
  </header>
  <main>
    <article>
      <header>文章标题与元信息</header>
      <section>章节一</section>
      <section>章节二</section>
    </article>
    <aside>相关推荐</aside>
  </main>
  <footer>版权信息</footer>
</body>
```

各标签的分工是：`<header>` 表示介绍性内容（logo、站点标题、导航组），它既可以是整个页面的页头，也可以是某个 article 或 section 的头部；`<nav>` 包裹主要的导航链接集合，页面可以有多个 nav（主导航、面包屑、分页）；`<main>` 是页面**主要内容**，一个页面只能出现一次，理想情况下屏幕阅读器可以"跳过页头页脚直达 main"；`<section>` 表示按主题划分的区块，规范建议它应该带有标题；`<article>` 表示独立完整、脱离页面也能成立的内容——一篇文章、一条评论、一张商品卡片，article 内部还可以再有自己的 header 和 footer；`<aside>` 表示与主内容弱相关的内容，如侧边栏、广告、名词解释；`<footer>` 是页脚或某个区块的尾部，通常放版权、作者、相关链接。

`<section>` 与 `<article>` 的区分初学者最容易困惑：问自己"这段内容放到 RSS 阅读器里单独出现还有意义吗"，有就是 article，只是文档的一个章节就是 section。而 `<div>` 与 `<span>` 是彻底**无语义**的容器，div 是块级、span 是行内，它们的定位是"最后手段"——只有当找不到合适的语义标签、又纯粹需要挂样式或脚本钩子时才使用。反过来说，也不要为了语义而语义，通篇 article/section 嵌套而无实际含义同样是坏味道。

### 2. 语义化的意义

**对 HTML 语义化的理解及好处**：语义化是指在构建页面时，根据内容的结构和含义选用恰当的标签——标题用 h1~h6、段落用 p、导航用 nav、强调用 em——而不是一律用 div 和 span 堆出视觉上相同的页面。一句话概括：**让标签表达"这是什么"，而不是只表达"长什么样"**。

语义化的好处体现在四个方面。**SEO**：搜索引擎爬虫不渲染视觉样式，它靠标签理解页面——标题层级决定内容权重，nav/main 帮助识别正文区域，语义化的页面更可能获得准确的收录和更好的排名。**可访问性**：屏幕阅读器依赖语义标签和隐含的 ARIA 角色工作，用户可以按标题层级跳转浏览、直接跳到 main 区域、从链接列表中导航，没有语义的 div 堆砌页面在听感上就是一锅粥。**可读性与可维护性**：语义化的源码结构一目了然，开发者不读样式就能看懂页面骨架，降低协作和重构成本。**环境兼容**：浏览器阅读模式、智能音箱、第三方抓取工具都依赖语义结构提取正文，语义化让内容在这些环境里依然可用。

## 八、HTML 常见面试问题

### 1. 行内元素、块级元素与行内块元素的区别

**块级元素**独占一行，默认宽度撑满父元素，可以直接设置 width 和 height，内部可以包含块级和行内元素，常见有 div、p、h1~h6、ul、ol、li、table、form。**行内元素**不换行、随内容伸缩，设置 width / height 无效，水平方向的 margin / padding 有效而垂直方向的 padding 只会撑开视觉效果、不影响布局，垂直 margin 完全无效，常见有 a、span、strong、em、code。**行内块元素**兼具两者特点：不换行，但可以设置宽高，默认宽度由内容决定，典型代表是 img、input、button、select、textarea 这些可替换元素和表单控件。

三者的本质区别在于格式化上下文中的排布方式和盒模型的生成方式，转换通过 `display: block | inline | inline-block` 完成。面试中可以补充一点：img 这类**可替换元素**虽然 display 默认是 inline，但浏览器对它们按 inline-block 的方式处理，所以能直接设置宽高。

### 2. HTML5 新增了哪些特性

HTML5 相对 HTML4 的变化可以按模块来记。**语义化标签**：新增 header、nav、main、section、article、aside、footer，取代 div 满天飞的写法。**多媒体**：原生 audio、video 元素取代 Flash。**绘图**：canvas 位图画布与内联 SVG。**表单增强**：新 input 类型（email、number、date、range、color 等）与新属性（placeholder、required、pattern、autocomplete），配合约束校验机制。**客户端存储**：localStorage、sessionStorage 和 IndexedDB，让数据可以不依赖 cookie 存在浏览器端。**通信与线程**：WebSocket 全双工通信、Web Worker 后台多线程、Server-Sent Events 服务器推送。**其他 API**：地理定位、拖放 API、History API（单页应用路由的基础之一）、iframe 的 sandbox 属性。**语法简化**：DOCTYPE 一行搞定，标签属性可以省略引号，容错规则标准化。回答时挑三四个方向展开说原理比把清单背完更能加分。

### 3. src 与 href 的区别

两者的核心区别是**关联资源还是嵌入资源，以及是否阻塞解析**。

`href`（hypertext reference）表示"超引用"，建立**当前文档与外部资源的关联**：资源本身不进入文档内部替换什么，浏览器会并行下载它，不阻塞 HTML 解析。使用 href 的是 a（导航目标）和 link（样式表、图标）。样式表虽然不阻塞解析，但会阻塞渲染（避免无样式内容闪烁），这是另一个话题。

`src`（source）表示"来源"，把资源**引入并替换当前元素的内容**，资源成为文档的一部分：img 的像素、iframe 的文档、script 的代码。其中 `<script src>` 默认会**阻塞** HTML 解析——浏览器必须停下来下载并执行脚本，因为脚本可能修改后续 DOM——所以才有 defer / async 这两个优化属性，也常拿它和 href 的并行加载对比。

一句话总结：**href 是引用（关联），src 是嵌入（替换）；script 的 src 会阻塞解析，link 的 href 不会**。

### 4. meta viewport 的作用

移动端浏览器为了兼容为桌面设计的网页，默认使用一个很宽的**布局视口**（layout viewport，通常是 980px）来排版页面，然后把整个页面缩小塞进屏幕——这就是为什么没有做适配的网页在手机上字非常小。`<meta name="viewport" content="width=device-width, initial-scale=1.0">` 的作用就是把布局视口宽度设置为设备的理想视口宽度（CSS 规范意义上的 device-width），并把初始缩放设为 1，使 CSS 像素与设备像素一一对应，页面按移动端的真实宽度排版。**它是所有移动端适配方案（rem、vw、媒体查询）生效的前提**，没有这一行，媒体查询里的 max-width 判断的是 980px 而不是手机屏幕宽度，整套方案都会失灵。

常用参数包括 `width=device-width`（视口宽度等于设备宽度，也可以写具体数值）、`initial-scale`（初始缩放比）、`maximum-scale` / `minimum-scale`（缩放范围）、`user-scalable`（是否允许用户手动缩放）。其中**不建议禁用缩放**（user-scalable=no）：它对低视力用户是严重的可访问性伤害，iOS Safari 10 之后也直接忽略了这条设置。
