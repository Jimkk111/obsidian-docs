### 1. KeepAlive是什么？

KeepAlive是Vue的内置组件，其作用是在多个组件动态切换时缓存被移除的组件实例。

KeepAlive默认会缓存其内部的所有组件实例，可以使用include和exclude实现有选择性地缓存，这两个prop可以接收以逗号分隔的字符串、正则表达式以及包含组件实例类型的数组。

max prop可以设置最大缓存数量，在缓存数量即将超过最大值时，会销毁最长时间没有被访问的缓存组件实例。

被KeepAlive缓存的组件实例被从DOM树上移走后仍存在于组件树上，只是状态变为了不活跃状态，重新被插入到DOM树上状态变回活跃状态。onActivated()和onDeActivated()分别注册两个状态的生命周期钩子。

### 2. 谈谈你对Vue的理解。

Vue是一个流行的JavaScript前端框架，专注于构建用户界面，其核心的响应式系统与虚拟DOM机制，让开发者声明式地编写模板，数据变化时自动更新视图。Vue采用组件化的开发思想，通过将模板、样式和逻辑封装成组件，实现代码的复用，便于维护。Vue支持引入插件增强功能，比如Vue Router系统管理路由、Vuex和Pinia系统管理应用状态，有利于开发大型的单页应用。

### 3. 谈谈你单页应用SPA的理解。

单页应用只请求一次HTML文件，后续的交互都通过动态替换页面内容实现，而不用重写加载整个页面。其路由机制原理是：JavaScript拦截默认行为，通过Histroy API或者哈希改变URL，然后异步请求数据并局部更新视图。单页应用的优点是加载速度快、响应流畅，缺点是首屏加载速度慢、对SEO不友好。

### 5. 谈谈你对双向绑定的理解。

双向绑定是指响应式数据与视图之间的双向影响关系，含义是当响应式数据发生改变时，自动触发视图的重新渲染，同样地当视图发生改变时，自动更新响应式数据。Vue中v-model指令可以实现表单与响应式数据的双向绑定。v-model是V-bind与v-on这两个指令的语法糖。v-bind建立起响应式数据指向视图的单向绑定关系，v-on绑定表单元素的事件监听器，实现自动更新响应式数据。

### 6. 谈谈你对v-show和v-if的理解。

v-show和v-if是vue中实现条件渲染的两个指令，二者在实现原理、初始渲染开销和切换开销上有区别。

首先是实现原理，v-show基于改变元素的display属性实现，v-show的值为false时，把display的值改变为none，为true时把display恢复为正常值，这个过程不会将元素从DOM树上移除；v-if是真正意义上的条件渲染，vue会根据条件表达式的值来决定元素的渲染，条件为false时，元素从DOM树上移除，条件为true时，创建新的DOM并插入DOM树渲染。

v-show的初始渲染开销大，因为无论如何元素要不要显示都要被创建；v-if的初始开销小，因为它是惰性的，只有当条件为true时才会创建DOM并渲染。

v-show的切换开销小，因为元素在初始时就创建好了，每次切换不需要重新创建；v-if的切换开销大，因为每次切换都需要重新创建元素，并且对于组件来说还会触发生命周期钩子的执行。。

总的来说，像Tap切换、折叠面板这种切换频繁的内容适合使用v-show；而像弹窗、图表这种切换频率小并且复杂的内容，适合使用v-if，减小初始渲染性能消耗。

### 7. 谈谈你对组件生命周期的理解。

组件生命周期是组件实例从创建、挂载、更新最后到卸载的完整生命流程，Vue提供了一组被称为生命周期钩子的函数允许我们在组件的不同生命周期插入我们想要执行的代码，包括请求数据、操作DOM元素等动作，这些生命周期钩子在选项式API和组合式API是有区别的。在选项式API里，有四对八个，创建时期的是beforeCreate、created，挂载时期的是beforeMount、mounted，更新时期的是beforeUpdate、updated，卸载时期的是beforeUnmounted、unmounted；在组合式API里，分别是onBeforeMount和onMounted、onBeforeUpdate和onUpdated、onBeforeUnmounted和onUnmounted，组合式api里没有组件创建时期的生命周期钩子，因为setup函数是在beforeMount之后、mounted之前执行的，有替代这两个钩子的作用。

Vu2和Vue3的选项式生命周期钩子的差别在于卸载时期的两个钩子，Vue2的叫beforeDestroy和destroyed。

### 8. Vue3响应式原理

Vue3的响应式系统原理基于Proxy实现，核心思路可以概括为：通过proxy对象拦截对原始对象的操作，在读取时收集依赖，在修改时触发更新。

首先，Proxy代理整个对象（包括数组、Map等类型），并可以拦截多种对象操作，例如读取、赋值、删除、in操作等。

接着是依赖收集与派发更新，这基于effect、trace和trigger实现。trace的作用是将当前正在运行的副作用函数与被访问的属性关联起来，这种关联关系用一个被称为targetMap的WeakMap实例存储，targetMap的键是原始对象，值是被称为depsMap的Map实例；depsMap的键是key，值是一个Set集合，称为dep，是key对应的依赖集合。trigger的作用是在原始对象发生改变时，取出被修改属性的所有依赖重新执行。

基于以上操作，Vue3提供了两个常用的用于创建响应式对象的api，分别是reactive()和ref()。reactive用于将对象类型（包括数组、`Map`、`Set`）转换为响应式代理。它会缓存已转换的对象，避免重复代理。访问嵌套属性时，会惰性地将嵌套对象也转为代理，而不是初始化时递归；`ref` 用于处理基本类型的响应式。它内部创建一个包含 `value` 属性的包装对象，并通过 `reactive` 实现响应式。在模板中使用时，`ref` 会自动解包；在 `reactive` 对象中作为属性时，也会自动解包为原始值。

### 六-1. Vue 的编译过程是怎样的？（template → AST → render → VNode）

**一句话总览**：Vue 组件经编译器编译后得到一个 **JavaScript 模块**，模板部分被编译成 **render 函数**。注意编译期产物是"函数代码"而不是 VNode——VNode 是 render 函数在**运行时执行后**的返回值：

```
template ──编译期──> AST ──> render 函数（JS 模块的一部分）
                              ↓ 运行时调用
                          VNode 树 ──diff/patch──> 真实 DOM
```

**1. SFC 先按块拆解，三条独立产物线**

`@vue/compiler-sfc` 把 `.vue` 文件解析成 descriptor，三块各自处理，最终汇成一个导出组件对象的 ES 模块：

| SFC 块 | 编译产物 | 去向 |
| --- | --- | --- |
| `<template>` | render 函数 | JS 模块 |
| `<script setup>` | setup() 函数 + 组件对象 | JS 模块 |
| `<style>` | 独立 CSS | 生产环境抽成 .css 文件；开发环境（vite）包成 JS 动态插入 `<style>` 标签（支持 HMR） |

scoped 样式的配套处理：CSS 侧改写成 `.title[data-v-7ba5bd90]`，同时把 scopeId 以 `__scopeId` 选项挂到组件对象上；运行时渲染时给该组件每个元素盖 `data-v-7ba5bd90` 属性（先写在 VNode 的 `scopeId` 字段上，落 DOM 时 setAttribute），两边靠属性选择器汇合。样式不进 render 函数。

**2. 模板编译三步：parse → transform → generate**

- **parse**：模板字符串解析成 AST（抽象语法树）；
- **transform**：遍历 AST 做优化标记——静态提升、patchFlag、事件缓存（cacheHandlers）；
- **generate**：把 AST 生成 render 函数代码。

例子：

```html
<template>
  <div class="hello">
    <h1>标题</h1>
    <p>{{ msg }}</p>
  </div>
</template>
```

编译产物（简化）：

```js
// 静态提升：静态节点只创建一次，重渲染直接复用、跳过 diff
const _hoisted_1 = { class: "hello" }
const _hoisted_2 = /*#__PURE__*/_createElementVNode("h1", null, "标题", -1 /* HOISTED */)

export function render(_ctx, _cache) {
  return (_openBlock(), _createElementBlock("div", _hoisted_1, [
    _hoisted_2,
    _createElementVNode("p", null, _toDisplayString(_ctx.msg), 1 /* TEXT */)
  ]))
}
```

从产物直接能看到编译优化：`_hoisted_*` 是**静态提升**（抽到函数外）；`1 /* TEXT */` 是 **patchFlag**（告诉运行时该节点只有文本可能变，diff 时只比文本）；`openBlock/createElementBlock` 构成 Block，收集 `dynamicChildren` 动态骨架。

**3. 运行时链条**

组件挂载 / 依赖更新时执行 render → 返回 VNode 树 → 与旧树 diff（patch）→ 更新真实 DOM。VNode 是描述节点"此刻长什么样"的普通 JS 对象，核心字段 `type/props/children/key/el`（身份与内容）+ `shapeFlag/patchFlag/dynamicChildren`（给 diff 引路的编译期标记）。模板里所有东西——元素（type 为标签字符串）、文本（`Symbol(Text)`）、注释（`Symbol(Comment)`）、组件（type 为组件对象）——都是 VNode，整棵 VNode 树是模板的 JS 对象镜像，`el` 字段挂载后指回真实 DOM。

**4. 编译发生在什么时候**

- 工程化项目：**构建时预编译**（vue-loader / @vitejs/plugin-vue），运行时只需 runtime-only 版 Vue（体积更小）；
- CDN 完整版（vue.global.js，内置 compiler）：**运行时编译**模板，有性能开销，生产环境不推荐。

**5. Vue2 对比**

编译目标同样是 render 函数，但产物调用 `createElement(h)` 风格 API，且没有静态提升、patchFlag——diff 需要全量逐层对比新旧 children，这正是"Vue3 编译优化"的考点。

| 层 | 对象 | 数量 | 生命周期 |
| --- | --- | --- | --- |
| 应用层 | app（+ appContext） | 一个应用一个 | createApp → unmount |
| 定义层 | 组件对象（**平级、互不嵌套**） | 一个组件一个 | 静态、长期存在 |
| 运行层 | 组件实例树 | 每个渲染位置一个 | 挂载期间持续存在 |
| 数据层 | VNode 树（subTree 拼接） | 每次渲染一批 | 即用即弃 |
| DOM 层 | 真实 DOM | — | patch 的目标 |

组件对象是全局一份的"图纸"；实例是图纸在每个渲染位置的"活化"（`<Item v-for="i in 10" />` = 一份定义 + 十个实例，定义共享、状态隔离）；render 是"一层"的——单次调用只产出本组件模板的 VNode 子树，子组件位置只留**占位 VNode**。挂载就是把平级定义组织成树的过程。

**1. 起点：createApp 很轻，根 VNode 在 mount 里手搓**

`createApp(App)` 只创建应用上下文（appContext：全局 `components`/`directives` 注册表、`config`、`provides`）并返回带配置 API 的 app 对象（`use` / `component` / `directive` / `provide` / `mount`...），`app._component` 存住根组件——此刻什么都没渲染。真正的起点在 `app.mount('#app')`：

```
app.mount('#app')
  ├─ 处理容器（根组件无 render/template 时用容器 innerHTML 当模板、清空容器）
  ├─ createVNode(App)            ← ★ 根 VNode 诞生（不是任何 render 的产物！）
  │     { type: App组件对象, component: null }
  ├─ render(vnode, container)    ← 同时记在 container._vnode 上（卸载/更新反查用）
  │     └─ patch(null, vnode, container)   ← 递归起点（旧树 = null）
  └─ 返回根实例的 proxy
```

根 VNode 的角色 = **应用级的占位 VNode**：别的占位活在父组件的 subTree 里，它没有父组件，宿主就是容器。注意有两个"根"，差一层：根 VNode（壳）→ App 实例 → subTree（App.render 的产物）。

对比 Vue2 的 `new Vue({...})`：直接创建根实例、全局注册挂在 Vue 构造函数上（全局单例、多应用互相污染）；Vue3 的全局注册挂在 app 上（应用级作用域，同页可多 app 共存、互不干扰，tree-shaking 友好）。

**2. 构建主循环：mountComponent 四拍**

```
patch(旧VNode, vnode, 容器)
 ├─ 元素 → mountElement：创建 DOM、递归 patch children、最后 insert 进父容器
 └─ type 是组件 → mountComponent：
     ① createComponentInstance（空壳实例 + 接线）
        instance.parent = 父实例                        ← 实例树的父边
        instance.vnode  = 占位VNode
        占位VNode.component = instance                  ← VNode → 实例
        instance.provides = Object.create(父实例.provides)  // provide/inject 注入链
     ② setupComponent：解析 props/slots/render；执行 setup() → setupState
     ③ setupRenderEffect：创建 update（render effect）并立即首次执行：
        subTree = render() 执行产出（子组件仍是占位）
        instance.subTree = subTree                      ← 实例 → 自己的渲染结果
     ④ patch(null, subTree, 容器)
        └─ 其中又有子组件占位 → mountComponent → ……递归到底
```

两棵树 + DOM 树的所有"边"都是这四拍里**顺手赋值的字段**：

| 树边 | 字段 | 赋值时机 |
| --- | --- | --- |
| VNode → 实例 | `vnode.component` | ① |
| 实例 → 父实例 | `instance.parent` | ① |
| 实例 → 渲染结果 | `instance.subTree` | ③ |
| VNode → DOM | `vnode.el` | mountElement（组件 VNode 的 el 回填为 subTree 根的 el） |

构建是**深度优先**的：mountElement 先把 children 全部建完才把自己 insert 进父容器——最深的叶子最先"落 DOM"。

**3. 关键机制：不拼接，靠字段连接**

- 父的 subTree 里子组件的位置**永远是占位 VNode**（children 是插槽函数，不是子的渲染内容）；
- 子的 render 结果只存在**子实例自己的 `subTree`** 上，不塞进父的树；
- "整棵 VNode 树"是逻辑概念（沿 `component` 链间接可达），物理上每个实例持有一段；Devtools 组件树就是这个逻辑视图；
- 真正的拼接发生在 **DOM 层**：子 subTree 的根元素 insert 到父 DOM 对应位置，占位 VNode 的 `el` 指向它做锚点；
- 插槽机制也源于此：插槽内容由父组件的 render 创建（插槽函数），却渲染进子组件的 subTree——结构归子、数据与创建时机归父。

**4. 更新与卸载：构建的镜像**

- ③ 创建的 `update`（render effect）是之后一切更新的发动机：render 执行期间访问的响应式数据都被它收集；数据变 → `instance.update()` → 新 subTree → `patch(旧subTree, 新subTree)`；
- patch 走到子组件占位：type 相同（sameVnode）→ **复用子实例**（只更新 vnode 指向与 props，子组件的 update 决定是否重新 render）；type 不同 → 卸载旧分支：`unmount` 停 effect、销毁 scope（响应式副作用统一清理）、递归 unmount(subTree)、摘 DOM——恰好是构建的镜像；
- **实例保留、只换 subTree**——组件是更新与状态的最小单位；keep-alive 缓存的正是实例（从树上摘下但不销毁，activated/deactivated 就是摘下/放回的钩子）；
- 更新流程不再经过 app（由实例的 effect 自驱动），app 的遗产只有 appContext 还在被引用（`resolveComponent` 查 `appContext.components`、应用级 provide 注入链）。

**5. 引用关系的三层形态（同一关系的三个时刻）**

| 时刻 | 结构 | 载体 |
| --- | --- | --- |
| 代码期（静态） | import 依赖图 | ES Module 的 import 语句 |
| 渲染中 | 对象引用 | VNode 的 `type` 字段直接持有子组件对象 |
| 挂载后 | 实例树 | `parent` / `component` / `subTree` |
