## 一、是什么

**拦截器（Interceptor）** 是 Spring MVC 提供的机制：在请求到达 Controller **之前**、处理**之后**插入统一逻辑。典型用途：登录校验、权限控制、操作日志。

与 Filter 的区别（常被一起问）：

| | Filter 过滤器 | Interceptor 拦截器 |
|---|---|---|
| 规范 | Servlet 规范（Tomcat 级） | Spring MVC（框架级） |
| 拦截范围 | **所有**请求（含静态资源） | 只拦 DispatcherServlet 处理的请求 |
| 能力 | 只认 request/response | 能拿到 Handler（哪个 Controller 哪个方法）、注入 Bean |
| 执行顺序 | 最外层，先于拦截器 | Filter 之后、Controller 之前 |

一个请求的完整链路：`Filter → DispatcherServlet → 拦截器 preHandle → Controller → 拦截器 postHandle/afterCompletion`，AOP 环绕在 Controller 方法那一层（见 [[web后端开发/JavaWeb/springboot/spring/AOP|AOP]]）。

## 二、三个方法

```java
public class LoginInterceptor implements HandlerInterceptor {

    // Controller 之前。返回 true 放行，false 拦断（请求到此结束）
    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response,
                             Object handler) {
        String token = request.getHeader("Authorization");
        if (token == null || !tokenIsValid(token)) {
            response.setStatus(401);
            return false;                          // 拦下，不再进 Controller
        }
        return true;
    }

    // Controller 返回之后、视图渲染之前（前后端分离下用得少）
    @Override
    public void postHandle(...) { }

    // 整个请求完成后（finally 性质）：无论成功失败都执行，适合清理
    @Override
    public void afterCompletion(...) { }
}
```

多个拦截器时：preHandle 按**注册顺序**正序执行，postHandle/afterCompletion **逆序**执行。

## 三、登录校验 + ThreadLocal 传递用户（实战套路）

**第 1 步：工具类用 ThreadLocal 存"当前登录用户"**

每个请求由一个独立线程处理，ThreadLocal 让同一次请求内的任何一层（Service/Mapper）都能拿到当前用户，而不用层层传参：

```java
public class UserContext {
    private static final ThreadLocal<Long> CURRENT_USER = new ThreadLocal<>();

    public static void set(Long userId) { CURRENT_USER.set(userId); }
    public static Long get()           { return CURRENT_USER.get(); }
    public static void clear()         { CURRENT_USER.remove(); }
}
```

**第 2 步：拦截器校验 + 存入**

```java
public class LoginInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response,
                             Object handler) throws IOException {
        String token = request.getHeader("Authorization");
        Long userId = TokenUtils.parse(token);          // 解析 token 拿到用户 id，无效返回 null
        if (userId == null) {
            response.setStatus(401);
            response.setContentType("application/json;charset=utf-8");
            response.getWriter().write("{\"code\":401,\"message\":\"未登录\"}");
            return false;
        }
        UserContext.set(userId);                        // 本次请求内随处可取
        return true;
    }

    @Override
    public void afterCompletion(...) {
        UserContext.clear();                            // 关键！见下
    }
}
```

**第 3 步：注册（不注册等于没写）**

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new LoginInterceptor())
                .addPathPatterns("/**")                                // 拦所有
                .excludePathPatterns("/users/login", "/users/register"); // 放行登录注册
    }
}
```

之后 Service 里直接 `Long me = UserContext.get();`，不用再从 Controller 传 userId 下来。

## ⚠️ 常见坑

1. **ThreadLocal 不清理 → 串用户**：Tomcat 线程是复用的，请求 A 结束不 `remove()`，下一个复用该线程的请求 B 可能读到 A 的用户。`afterCompletion` 里必须 `clear()`。
2. **拦截器是 `new` 出来的不是 Bean**：注册时 `new LoginInterceptor()`，里面不能直接 `@Autowired`；需要用别的 Bean 时，把拦截器也注册成 Bean（`registry.addInterceptor(loginInterceptor)` 注入使用）。
3. **放行路径没配全**：登录、注册、验证码、静态资源、跨域预检（OPTIONS）都要放行。
4. **拦截器抛异常**：会被全局异常处理接住（见 [[web后端开发/JavaWeb/springboot/spring-mvc/异常处理|异常处理]]），但登录失败场景通常直接写响应更直观。
