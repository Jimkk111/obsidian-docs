定制 Spring MVC 行为的两个入口。注意区分：改**应用配置**（端口、数据源）用 application.yml，见 [[web后端开发/JavaWeb/springboot/配置文件|配置文件]]；本篇是**框架行为**定制。

## 一、WebMvcConfigurer（推荐）

接口，方法都有默认实现，**只覆盖你关心的那一个，其余默认配置全部保留**：

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    // 例 1：注册拦截器（拦截器怎么写见「拦截器」笔记）
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new LoginInterceptor())
                .addPathPatterns("/**")
                .excludePathPatterns("/login", "/register");
    }

    // 例 2：静态资源映射：URL /upload/** 映射到磁盘目录
    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        registry.addResourceHandler("/upload/**")
                .addResourceLocations("file:D:/upload/");
    }

    // 例 3：跨域
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOrigins("http://localhost:5173")     // 前端地址
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true);
    }
}
```

默认静态资源位置（不用配置直接放文件就能访问）：`classpath:/static/`、`/public/`、`/resources/`、`/META-INF/resources/`。

## 二、WebMvcConfigurationSupport（慎用）

继承这个类 = **接管 Spring MVC 全部配置，默认自动配置全部失效**——静态资源映射、消息转换器、参数解析器等都要自己重新配。原笔记只说了"它提供扩展点"，没说代价：**绝大多数"静态资源突然 404、JSON 解析失效"的坑，都来自有人继承了它**。

只有需要彻底重写 MVC 行为时才用它。日常需求 WebMvcConfigurer 全部覆盖，优先级：**WebMvcConfigurer（够用）> WebMvcConfigurationSupport（重写一切）**。

## 三、跨域 CORS 补充

前后端分离（如 Vite 5173 端口调后端 8080）必然遇到浏览器跨域限制。除了上面 `addCorsMappings` 全局配置，也可在接口/类上加 `@CrossOrigin` 局部放行。

原理一句话：浏览器对"非简单请求"先发一个 `OPTIONS` 预检，服务端确认放行才发真请求。所以配置 CORS 后仍报跨域，常见原因是**拦截器/登录校验把 OPTIONS 预检请求也拦了**——记得放行 `OPTIONS`（或把预检路径加进 excludePathPatterns）。

## ⚠️ 常见坑

1. **实现 WebMvcConfigurer 又继承 WebMvcConfigurationSupport** → 后者吞掉一切默认配置，只留后者自己的
2. **配置了跨域还报跨域** → 预检 OPTIONS 请求被拦截器拦截返回 401
3. **静态资源 404** → 有自定义 `WebMvcConfigurationSupport`；或自定义资源映射覆盖了默认路径
4. **拦截器没生效** → 只写了拦截器类，忘了在 addInterceptors 注册
