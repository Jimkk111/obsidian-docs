## 一、Spring 家族先理清

| 名称 | 定位 | 一句话 |
|---|---|---|
| **Spring Framework** | 地基 | IoC 容器 + AOP 等核心能力，一切 Spring 项目的基础 |
| **Spring MVC** | Web 框架 | 处理 HTTP 请求/响应，属于 Spring Framework 的一部分 |
| **Spring Boot** | 快速构建工具 | 简化 Spring 项目的搭建和配置，不实现新功能 |
| Spring Cloud | 微服务 | 分布式系统开发，建立在 Spring Boot 之上 |

初学最常混淆的点：**Spring Boot 不是 Spring 的替代品，而是"帮你把 Spring 项目快速搭起来的脚手架"**。学 Spring Boot 本质上还是在学 Spring（IoC/DI、MVC、事务），Spring Boot 负责的是"少写配置、快速启动"。

## 二、Spring Boot 解决什么问题

传统 SSM（Spring + SpringMVC + MyBatis）时代的三大痛点：

1. **依赖管理繁琐**：要自己引几十个 jar，版本稍有冲突就是 `ClassNotFoundException`、`NoSuchMethodError`
2. **配置繁琐**：一堆 XML（`applicationContext.xml`、`spring-mvc.xml`……），配置写错的报错还很难看懂
3. **部署麻烦**：打 war 包，还要先装 Tomcat 再丢进去

Spring Boot 的核心思想是**约定优于配置（Convention over Configuration）**：按大家公认的默认方式约定好，你不配置就用默认值，只覆盖需要定制的部分。四大核心特性：

- **起步依赖（starter）**：引一个 `spring-boot-starter-web`，它关联的 Spring MVC、Tomcat、Jackson 等依赖和兼容版本全部自动带齐
- **自动配置（Auto Configuration）**：根据你引入的依赖，自动创建好需要的 Bean（引了 MyBatis 就自动配好 SqlSessionFactory），条件不满足的配置自动跳过
- **内嵌服务器**：内置 Tomcat，直接 `java -jar app.jar` 运行，不用装外部容器
- **Actuator（生产监控，了解）**：暴露健康检查、指标等运维端点

## 三、快速入门

### 1. 环境准备

- JDK 17+（Spring Boot 3.x 要求；2.x 只需 JDK 8+）
- Maven 3.6+（或 Gradle）
- IDEA（社区版即可，旗舰版对 Spring 支持更全）

### 2. 创建项目

官方脚手架 [start.spring.io](https://start.spring.io)（IDEA 新建项目时选 **Spring Initializr**，本质一样）：

- Project：Maven / Language：Java / Packaging：**Jar**
- Spring Boot 版本：选 3.x 稳定版
- Dependencies：勾 **Spring Web**

### 3. 认识 pom.xml

```xml
<!-- 父工程：管理了几百个常用依赖的"兼容版本号"，子项目引依赖不用写版本 -->
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.x.x</version>
</parent>

<dependencies>
    <!-- 起步依赖：web 场景全家桶（spring-mvc + tomcat + jackson...） -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
</dependencies>
```

### 4. 启动类

```java
@SpringBootApplication   // 组合注解 = @SpringBootConfiguration + @EnableAutoConfiguration + @ComponentScan
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

- `@SpringBootConfiguration`：本类是配置类
- `@EnableAutoConfiguration`：开启自动配置（Spring Boot 魔法的开关）
- `@ComponentScan`：扫描本类**所在包及其子包**下的 `@Component`/`@Service`/`@Controller` 等注解

### 5. 第一个接口

```java
@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello() {
        return "hello springboot";
    }
}
```

启动 main 方法，浏览器访问 `http://localhost:8080/hello` 即可。

## 四、项目结构约定

```
src/
├── main/
│   ├── java/com/example/demo/
│   │   ├── DemoApplication.java   # 启动类，约定放在根包
│   │   ├── controller/            # 表现层
│   │   ├── service/               # 业务层（接口 + impl 子包）
│   │   ├── mapper/                # 持久层
│   │   └── entity/  /pojo/        # 实体类
│   └── resources/
│       ├── application.yml        # 核心配置文件
│       ├── static/                # 静态资源（js/css/图片）
│       └── templates/             # 服务端模板页面（前后端分离用不到）
└── test/                          # 测试代码，结构镜像 main
```

⚠️ **启动类必须放在根包**（所有业务包的上一级）：因为 `@ComponentScan` 默认只扫它所在包及子包，启动类放深处会导致扫描不到别的包的 Bean，报 `NoSuchBeanDefinitionException`。

## ⚠️ 版本差异（踩坑预告）

Spring Boot 2.x 和 3.x 的代码差异主要在一处：**Servlet 相关包名**。

- 3.x（JDK 17+）：`import jakarta.servlet.*`
- 2.x（JDK 8+）：`import javax.servlet.*`

网上老教程、老视频大多是 2.x 写法，报"找不到 javax.servlet"时，把 `javax` 换成 `jakarta` 基本就能解决。学新项目直接用 3.x。
