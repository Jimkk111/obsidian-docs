# 财经新闻项目真实 Bug 复盘

## 问题/背景

对自己的财经新闻全栈项目（Spring Boot 3.4 + MyBatis-Plus + Redis + MySQL，Docker 部署阿里云）做功能质量审查与修复，共发现并修复 20+ 个真实缺陷，涉及并发一致性、事务边界、异常纪律、缓存、安全。每个坑都是面试可讲的活案例。

## 原因分析与解决（按知识点分组）

### MyBatis-Plus 相关

1. **不可变 List 上 add → UnsupportedOperationException**
   `Stream.toList()` 返回不可变列表，采集流水线里往"最近指纹列表"追加新指纹时抛异常，且异常发生在 `insert` **之后**——数据已入库却被误报 FAILED。改 `Collectors.toCollection(ArrayList::new)`。
   *教训：`toList()` / `List.of()` / `Map.of()` 都不可变，结果还要增删就必须显式 new ArrayList。*

2. **saveNews 根本不落 url 字段**
   工具方法接收 url 参数但构建实体时漏 set，爬回来的新闻没有来源链接，URL 去重无从谈起。*教训：参数列表和实体字段不对账，靠代码审查或审计表发现。*

3. **checkUrlsExist 拿 URL 和 title 字段比较**
   `eq(News::getTitle, canonicalUrl)`——Lambda 方法引用手滑选错字段，去重统计完全错误且无报错。*教训：Lambda 引用错了编译器不报错，只能靠 review 和测试。*

4. **N+1 查询（窗口函数修复）**
   会话列表逐个查最后一条消息。改 `ROW_NUMBER() OVER (PARTITION BY session_id ORDER BY created_at DESC)` 一次取回，21 次查询变 2 次。

5. **@Transactional 里做远程调用/吞异常**
   - `chat` 事务内调 AI HTTP，上游慢时长期占用 DB 连接 → 远程调用移出事务。
   - `saveNews` 事务内 `catch(Exception)` 返回字符串，正文入库成功而标签失败照样提交 → 半成品数据。
   - 发邮件在事务里且失败被吞，接口仍返回"已发送" → 用户收不到码系统不自知。
   *教训（本组最核心）：事务内不做远程 IO；异常路径不许伪装成功。*

### MySQL 相关

6. **唯一性竞态**：注册/收藏/历史全是 exists-check-then-insert，并发重复。解法：数据库唯一索引兜底 + 捕获 `DuplicateKeyException` 转 409 业务码；浏览历史用 `ON DUPLICATE KEY UPDATE` 幂等 upsert。

7. **逻辑删除配置 `NOW()` 是合法的**
   一直以为 `logic-delete-value: "NOW()"` 会被当字面字符串，实际 MP 原样拼进 SQL（生成 `SET deleted_at=NOW() WHERE deleted_at IS NULL`），功能正常。**教训：改"看起来错"的配置前先验证，实测后确认不改，避免无谓回归。**

8. **原子更新**：浏览量 select→set→updateById 并发丢更新，改 `UPDATE ... SET views = views + 1`；并补了基于 Redis SETNX 的同用户 1 小时去重防刷。

9. **schema 漂移**：线上库结构比仓库 init.sql 新（多出 url/指纹列），迁移时连报两次 Duplicate column。*教训：迁移脚本要幂等意识，先 SHOW 再执行；库结构变更必须回流仓库。*

### Redis 相关

10. **缓存一致性**：先更 DB 再删缓存，删除失败只 warn → 长期脏读。改延迟双删（删后 1 秒调度再删）+ 所有缓存带 TTL 作脏读上限。

11. **RedisTemplate 取值强转坑**：`get()` 出来的数字可能是 Integer 也可能是 Long，直接 `(Long)` 强转 ClassCastException。用 `instanceof Number n ? n.longValue() : 0`。

12. **降级纪律**：所有 Redis 调用包 try-catch 降级放行（验证码限流、浏览去重、缓存），Redis 挂了核心业务照常。*Redis 是增强件不是依赖件。*

### 部署/配置相关

13. **YAML 重复键启动失败**：往 application.yml 加 `crawler:` 时没发现文件里已有一段，SnakeYAML 报 DuplicateKeyException 拒绝启动。*教训：改配置文件前先 grep 键名。*
14. **compose 变量只写注释没注入**：爬虫开关在 compose 里只是注释行，`.env` 设了也传不进容器。*教训：环境变量链路（.env → compose → Spring）每跳都要验证。*
15. **验证码无防爆破**：无尝试次数限制、发送无频率限制。解法：5 次错误销毁并锁定、60s/条 + 24h/10 条（INCR 后返回 1 才 expire，否则每次重置 TTL）。
16. **git add . 提交了数据库备份**：服务器目录里备份 dump 差点进仓库（含密码哈希）。*教训：服务器目录禁止 git add .；backup*/*.env 写 .gitignore。*

## 经验教训

- **异常路径的处理纪律决定功能质量**：正常路径基本都对，出错路径大量被吞掉或伪装成功才是质量差的根源。
- **并发问题以数据库约束兜底**：唯一索引 > 原子 SQL > 乐观锁 > 悲观锁，代价递增。
- **审计表价值巨大**：`crawl_audit` 记录每篇文章 SAVED/DUP/REJECTED/FAILED 及原因，"探测到却没入库"从黑盒变成可查询——不可变 List 那个 bug 就是它先暴露的。
- **修一类问题补一类测试**：并发用 Testcontainers 验证约束，外部调用 mock 失败路径。
