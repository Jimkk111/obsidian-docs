## 十、已整理答案

> 答案为要点版，详细内容见对应笔记。

### 1. Redis 是什么？有哪些应用场景？

Redis 是基于内存的 key-value 数据库，C 语言编写、单线程执行命令、IO 多路复用、支持持久化与高可用集群，性能可达 10w+ QPS。场景：**缓存**（最核心）、计数器 / 排行榜、分布式锁、消息队列、集群会话共享、附近的人（GEO）。详见 [[web后端开发/数据库/Redis/介绍|介绍]]。

### 2. Redis 为什么快？

① 纯内存操作无磁盘 IO；② 数据结构高效（SDS、哈希表、跳表、紧凑编码）；③ 命令执行单线程，无上下文切换和锁竞争；④ IO 多路复用（epoll）支撑海量连接。详见 [[web后端开发/数据库/Redis/介绍|介绍]]。

### 3. Redis 是单线程还是多线程？

**命令执行始终是单线程**（因此不用考虑并发安全）；6.0 引入的多线程只负责**网络 IO 读写与协议解析**；持久化、异步删除由后台线程完成。详见 [[web后端开发/数据库/Redis/介绍|介绍]]。

### 4. Redis 有哪些数据类型？各自的使用场景？

| 类型 | 场景 |
| ---- | ---- |
| String | 缓存对象 JSON、计数器（INCR 原子）、验证码 TTL、分布式锁 |
| Hash | 对象字段级读写、购物车 |
| List | 消息队列（简单）、最新列表 |
| Set | 去重（点赞）、交并差（共同关注）、抽奖 |
| ZSet | 排行榜、延迟队列（score = 时间戳） |
| 扩展类型 | BitMap 签到、HyperLogLog UV、GEO 附近的人、Stream 可靠队列 |

详见 [[web后端开发/数据库/Redis/String|String]] 等各类型笔记与 [[web后端开发/数据库/Redis/其他类型|其他类型]]。

### 5. 五种类型的底层编码？

小数据用紧凑结构、大数据转高效结构：String → int / embstr（≤44B）/ raw；Hash → listpack → hashtable；List → quicklist；Set → intset（全整数小集合）→ hashtable；ZSet → listpack → skiplist + dict。详见各类型笔记。

### 6. ZSet 为什么用跳表不用红黑树？

跳表 O(logN) 且实现简单；**范围查询**沿底层链表顺序遍历天然高效（排行榜场景核心诉求）；插入删除只改指针。B+ 树是为磁盘按页读取设计的多路结构，Redis 纯内存不需要。详见 [[web后端开发/数据库/Redis/ZSet|ZSet]]。

### 7. String 的 SDS 有什么优势？

结构头记录长度（STRLEN O(1)）；**二进制安全**可存任意字节；空间预分配 + 惰性释放减少内存重分配。详见 [[web后端开发/数据库/Redis/String|String]]。

### 8. 排行榜怎么做？

ZSet：`ZINCRBY rank 1 商品` 累计分数，`ZREVRANGE rank 0 9 WITHSCORES` 取 Top10，`ZREVRANK` 查排名，`ZSCORE` 查分数。详见 [[web后端开发/数据库/Redis/ZSet|ZSet]]。

### 9. Hash 和 String 存对象怎么选？

String+JSON 整存整取、简单省一点内存，但改一个字段要整体序列化重写；Hash 支持字段级读写（HSET/HGET/HINCRBY），适合字段多且更新频繁的对象。详见 [[web后端开发/数据库/Redis/Hash|Hash]]。

### 10. RDB 和 AOF 的原理与优缺点？

RDB：定时全量二进制快照（BGSAVE fork 子进程），文件小、恢复快，但两次快照间的数据会丢。AOF：追加每条写命令，everysec 刷盘最多丢 1 秒，文件大、恢复慢（重放），可通过重写压缩。生产常用：AOF everysec + 混合持久化（重写文件 = RDB 全量头 + AOF 增量尾）。详见 [[web后端开发/数据库/Redis/持久化|持久化]]。

### 11. BGSAVE 如何工作？什么是写时复制？

主进程 fork 子进程，父子共享物理内存；子进程把内存快照写入临时 RDB 再原子替换。fork 后主进程的新写入触发操作系统**复制内存页**再写（COW），保证子进程看到的是 fork 瞬间的数据、主进程不停服。详见 [[web后端开发/数据库/Redis/持久化|持久化]]。

### 12. AOF 刷盘策略与 AOF 重写？

always（每命令刷，最多丢 1 条）/ **everysec（默认，每秒，最多丢 1 秒）** / no（交 OS）。重写：根据内存**最终状态**生成最小等价命令集（100 次 INCR 合并为 1 条 SET），fork 子进程执行，期间新命令写双缓冲最后合并。详见 [[web后端开发/数据库/Redis/持久化|持久化]]。

### 13. Redis 如何删除过期 key？

**惰性删除**（访问时检查）+ **定期删除**（默认每秒 10 次，每次抽 20 个带 TTL 的 key，删除已过期的，过期比例 > 25% 则继续）结合，平衡 CPU 与内存。详见 [[web后端开发/数据库/Redis/过期与内存淘汰|过期与内存淘汰]]。

### 14. 内存淘汰策略有哪些？

内存达到 maxmemory 后按 `maxmemory-policy` 淘汰，共 8 种：默认 **noeviction**（不淘汰、写入报错）；对设置过期时间的 key：volatile-ttl / volatile-random / volatile-lru / volatile-lfu；对全部 key：allkeys-lru / allkeys-lfu / allkeys-random。LRU/LFU 是**随机采样的近似实现**（默认采样 5 个）。缓存场景常用 allkeys-lru 或 allkeys-lfu。详见 [[web后端开发/数据库/Redis/过期与内存淘汰|过期与内存淘汰]]。

### 15. Redis 事务？与 MySQL 事务的区别？

MULTI 入队 → EXEC 原子执行（不被其他客户端插队）。但**不支持回滚**：运行时某条命令失败，其余照常执行（官方：错误应止于开发期，无回滚保持简单快速）。隔离性靠 WATCH 乐观锁实现（被监视 key 被修改则事务放弃）。详见 [[web后端开发/数据库/Redis/事务与Lua|事务与Lua]]。

### 16. Pipeline 和事务的区别？

Pipeline 是客户端**批量传输命令**减少网络往返，不保证原子（命令间可能被插队）；事务保证执行不被插队，但每条命令的响应仍逐条返回。二者可结合使用。详见 [[web后端开发/数据库/Redis/事务与Lua|事务与Lua]]。

### 17. 主从复制的原理？

主从各维护 replication id + offset。首次连接（psync ? -1）触发**全量同步**：主库 bgsave 生成 RDB 发送，期间新写命令暂存 repl_baklog，从库载入 RDB 后再补增量。短暂断线重连（psync replid offset）：差量还在 repl_baklog（环形缓冲，默认 1mb）中则**增量同步**，被覆盖则退化为全量。详见 [[web后端开发/数据库/Redis/主从与集群|主从与集群]]。

### 18. 哨兵的故障转移流程？

① 单个哨兵 ping 超时 → **主观下线**；② ≥ quorum 个哨兵认同 → **客观下线**；③ 哨兵间投票（Raft 思想）选出 leader；④ leader 按优先级（replica-priority）→ offset（数据最新）→ runid 最小 选新主；⑤ 其余从库指向新主，旧主恢复后降为从，哨兵发布订阅通知客户端。详见 [[web后端开发/数据库/Redis/主从与集群|主从与集群]]。

### 19. 分片集群原理？为什么 16384 个槽？

数据按 `CRC16(key) % 16384` 映射到 16384 个哈希槽，槽分配给各主节点；请求到错误节点返回 MOVED 重定向。为什么 16384：① 心跳包携带槽位图 16384 位 = 2KB 合适，65536 太大；② 官方建议集群 ≤ 1000 节点，槽够用；③ 槽少时位图压缩率低。详见 [[web后端开发/数据库/Redis/主从与集群|主从与集群]]。

### 20. 旁路缓存模式？

读：先读缓存，命中返回；未命中查库、回写缓存（带 TTL）。写：**先更新数据库，再删除缓存**——删而非改（惰性加载、避免并发更新乱序）；先库后删（先删缓存会让并发读把旧值写回，脏数据概率更高）。详见 [[web后端开发/数据库/Redis/缓存|缓存]]。

### 21. 如何保证缓存一致性？

「先库后删」仍有小概率脏数据。增强：**延迟双删**（删缓存 → 更新库 → 延迟几百 ms → 再删一次）；Canal 订阅 binlog 异步删缓存（解耦推荐）；目标都是**最终一致**。详见 [[web后端开发/数据库/Redis/缓存|缓存]]。

### 22. 穿透、击穿、雪崩的区别与解决？

- **穿透**：数据不存在、缓存永不生效 → 空值缓存（短 TTL）/ 布隆过滤器 / 参数校验。
- **击穿**：热点 key 过期瞬间高并发回源 → 互斥锁重建 / 逻辑过期（异步重建返回旧值）。
- **雪崩**：大量 key 同时过期或实例宕机 → TTL 加随机值 / 高可用集群 / 限流熔断降级。

详见 [[web后端开发/数据库/Redis/缓存|缓存]]。

### 23. 如何用 Redis 实现分布式锁？

`SET lock 线程标识 NX EX 10` 一条命令完成加锁 + 过期（防死锁、防两条命令之间崩溃）；value 存唯一线程标识；释放用 **Lua 脚本**「校验是自己 + 删除」原子执行，解决**误删他人锁**问题。生产直接用 Redisson。详见 [[web后端开发/数据库/Redis/分布式锁|分布式锁]]。

### 24. Redisson 的原理？

可重入：锁为 Hash 结构，field = 线程标识，value = 重入计数，加解锁用 Lua 维护。看门狗：不指定 leaseTime 时锁 30s，后台每 10s 检查持有即续期，业务没执行完不会过期，进程宕机锁自动释放。重试：基于发布订阅，锁释放时唤醒等待线程。主从锁丢失可用 RedLock（有争议）。详见 [[web后端开发/数据库/Redis/分布式锁|分布式锁]]。
