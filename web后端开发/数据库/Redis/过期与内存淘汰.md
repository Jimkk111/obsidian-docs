# 过期删除与内存淘汰

Redis 能当缓存用，靠两层机制：key 到期后被**删除**（过期删除策略）；内存占满后按规则**淘汰**部分 key（内存淘汰策略）。

## 过期 key 的存储

每个库维护一张**过期字典（expires）**：key → 过期时间戳。`EXPIRE` 就是往字典里写一条，`TTL` 即查这张表。到期后 key **不会立刻消失**，何时删除取决于删除策略。

## 过期删除策略（Redis = 惰性 + 定期）

| 策略 | 做法 | 缺点 |
| ---- | ---- | ---- |
| 定时删除 | 每个 key 到期立刻删（定时器） | 过期 key 多时 CPU 压力大 |
| 惰性删除 | 访问 key 时检查，过期才删 | 没人访问的过期 key 一直占内存 |
| 定期删除 | 周期性抽查删除 | 频率与时机要折中 |

Redis 的实现（惰性 + 定期结合）：

- **惰性删除**：读写任何 key 前先检查是否过期，过期则删除并按不存在处理。
- **定期删除**：默认每秒 10 次（`hz 10`），每次从**设置了过期时间**的 key 中随机抽 20 个检查，删除其中已过期的；若本轮过期比例 **超过 25%**，立刻再抽一轮；单轮有时间上限，防止死循环阻塞。
- 4.0+ 支持异步删除（lazyfree）：删除大 key 时由后台线程回收内存，`UNLINK` 即异步版 `DEL`。

## 内存淘汰策略

前提：`maxmemory`（默认 0，即不限制）。达到上限后，写命令如何处理由 `maxmemory-policy` 决定。

**默认策略 noeviction**：内存满后所有写命令报 OOM 错误（读和删除正常）——缓存场景通常不希望这样。

八种策略（4.0+）：

| 策略 | 淘汰范围 | 规则 |
| ---- | ---- | ---- |
| noeviction（默认） | — | 不淘汰，写入报错 |
| volatile-ttl | 设置了过期时间的 key | 剩余 TTL 越小越先淘汰 |
| volatile-random | 设置了过期时间的 key | 随机淘汰 |
| volatile-lru | 设置了过期时间的 key | 近期最少使用 |
| volatile-lfu | 设置了过期时间的 key | 最不经常使用 |
| allkeys-lru | 全部 key | 近期最少使用 |
| allkeys-lfu | 全部 key | 最不经常使用 |
| allkeys-random | 全部 key | 随机淘汰 |

说明：

- volatile-* 只在没有 key 设置过期时间时退化为报错。
- LRU / LFU 是**近似实现**：随机采样 `maxmemory-samples`（默认 5）个 key，淘汰其中最符合条件的一个，而非维护全局 LRU 链表（省内存省开销）。
- **LFU**（4.0+）按访问频率淘汰（对数计数器 + 随时间衰减），比 LRU 更适合缓存——LRU 可能被偶发的批量扫描「冲掉」真正的热点数据。

```conf
maxmemory 1gb
maxmemory-policy allkeys-lfu
```

> 纯缓存场景常用 allkeys-lru / allkeys-lfu；对冷数据可再叠加 TTL 兜底。
