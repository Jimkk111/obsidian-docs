# 其他类型

五种基本类型之上，Redis 还提供了一批面向特定场景的扩展类型（面试加分项）。

## BitMap 位图

把 String 的字节当**位数组**用，每一位 0/1，极省内存（1 亿用户 1 天的活跃标记约 12MB）。

| 命令 | 说明 |
| ---- | ---- |
| SETBIT key offset 1 | 设置第 offset 位 |
| GETBIT key offset | 读取某位 |
| BITCOUNT key | 统计值为 1 的位数 |
| BITPOS key bit | 找第一个 0/1 的位置 |

**签到场景**（用户 1001，2026 年 9 月，offset = 日期 - 1）：

```bash
SETBIT sign:1001:202609 9 1     # 9月10日签到
GETBIT sign:1001:202609 9       # 今天是否已签
BITCOUNT sign:1001:202609       # 本月签到天数
```

还适合：每日活跃用户统计（offset = userId）、在线状态。

## HyperLogLog（HLL）

**基数统计**（去重计数）的近似算法：每个 key 固定约 **12KB**，标准误差 0.81%，用极小内存统计海量数据的去重个数。

```bash
PFADD uv:2026-09-10 u1 u2 u3    # 记录访客（重复自动去重）
PFCOUNT uv:2026-09-10           # 估算 UV
PFMERGE uv:week uv:day1 uv:day2 # 合并多天
```

场景：页面 UV、搜索去重词数。要求**精确**去重时用 Set / Hash（但内存开销大得多）。

## GEO 地理位置

提供经纬度的存储与距离 / 范围计算，**底层就是 ZSet**：用 geohash 把二维经纬度编码为 52-bit 整数作为 score 存入 ZSet，从而复用其有序检索能力。

```bash
GEOADD shop:geo 116.397 39.909 北京站        # 经度 纬度 成员
GEOADD shop:geo 116.410 39.918 朝阳门店
GEOSEARCH shop:geo FROMMEMBER 北京站 BYRADIUS 3 km ASC COUNT 5
# 以"北京站"为中心搜 3km 内的店铺，按距离升序取 5 个
GEODIST shop:geo 北京站 朝阳门店 km          # 两点距离
```

场景：附近的人、附近店铺、同城配送。> GEOSEARCH 为 6.2+ 命令，旧命令 GEORADIUS 已废弃。

## Stream 消息列表（5.0+）

专为**消息队列**设计的类型，弥补 List 队列的不足：**可持久化、支持消费组（多消费者负载均衡）、ACK 确认与 pending 重试、消息可回溯**。

```bash
XADD mq * order 1001                          # 发消息，* 自动生成 id
XGROUP CREATE mq g1 0                         # 创建消费组
XREADGROUP GROUP g1 c1 COUNT 1 BLOCK 5000 STREAMS mq >   # 消费组内读取
XACK mq g1 <消息id>                           # 确认（处理完成）
XPENDING mq g1                                # 查看待确认消息
```

> 对照：发布订阅（SUBSCRIBE / PUBLISH）可实时广播，但**不持久化、离线丢消息、无 ACK**，不适合做可靠队列。

## 选型速查

| 需求 | 推荐类型 |
| ---- | ---- |
| 对象缓存 | String（JSON）/ Hash |
| 排行榜、延迟队列 | ZSet |
| 去重、共同好友 | Set |
| 简单队列 / 最新列表 | List；可靠队列用 Stream |
| 签到、活跃标记 | BitMap |
| 海量去重计数（允许误差） | HyperLogLog |
| 附近的人 / 店 | GEO |

> Redis 8.0 还新增了 Vector Set（向量集合，beta），面向 AI 语义搜索场景，了解即可。
