# 存储引擎

存储引擎（Storage Engine）是 MySQL 插件式架构中**真正负责数据存储、提取和索引管理**的组件，其余部分（SQL 解析、优化、内置函数等）跨引擎共享。存储引擎是**表级别**的属性，同一数据库中不同的表可以使用不同引擎。

```sql
SHOW ENGINES;                                  -- 查看支持的引擎（Support 列 DEFAULT 即默认）
SHOW CREATE TABLE tb_user;                     -- 查看某张表用的引擎
CREATE TABLE t (...) ENGINE = InnoDB;          -- 建表时指定
ALTER TABLE t ENGINE = MyISAM;                 -- 修改引擎（重建表，代价大）
```

## 一、InnoDB（默认）

MySQL 5.5 起的默认引擎，面向高并发、需要事务的业务场景，核心特性：

- **ACID 事务**：支持 COMMIT / ROLLBACK / 崩溃自动恢复（redo log / undo log）。
- **行级锁**：锁粒度小，并发写入能力强（锁加在索引上，见 [[web后端开发/数据库/MySql/锁|锁]]）。
- **外键**：唯一支持外键的常用引擎。
- **MVCC**：多版本并发控制，读写不冲突（见 [[web后端开发/数据库/MySql/MVCC|MVCC]]）。
- **索引组织表**：数据本身按主键组织成聚簇索引（见 [[web后端开发/数据库/MySql/索引|索引]]）。

### 逻辑存储结构

```
表空间 (Tablespace) → 段 (Segment) → 区 (Extent, 1MB) → 页 (Page, 16KB) → 行 (Row)
```

- **页**是 InnoDB 磁盘管理的**最小单位**（默认 16KB，B+ 树的一个节点就是一页），从磁盘加载到内存 Buffer Pool 也是以页为单位。
- **区**由 64 个连续页组成（1MB），按区分配可减少随机 IO。
- **段**分为数据段（叶子节点）、索引段（非叶子节点）、回滚段等。

### 内存与磁盘结构（官方 15.5）

- **内存侧（服务器启动时申请）**：
	- Buffer Pool：缓存热点数据页和索引页，是最重要的内存参数（`innodb_buffer_pool_size`，建议设为物理内存的 60%~80%）。
	- Change Buffer：二级索引页不在缓冲池时的写优化。
	- Adaptive Hash Index：自动为热点索引页建哈希索引。
	- Log Buffer：redo log 写盘前的缓冲。
- **磁盘侧**：
	- 表空间文件：`innodb_file_per_table` 默认开启，每张表一个 `.ibd` 文件。
	- redo log（重做日志，WAL）：保证持久性，崩溃后恢复已提交的数据。
	- undo log（回滚日志）：保证原子性，支撑 MVCC 版本链。
	- Doublewrite Buffer：防止「页断裂」（半页写入）。

## 二、MyISAM

MySQL 5.5 之前的默认引擎，不支持事务、行锁、外键：

- 表级锁，读写、写写均互斥，并发写入能力弱。
- 索引与数据分离存储（`.MYI` 索引文件 + `.MYD` 数据文件），属于**非聚簇**结构，二级索引叶子直接存数据文件地址。
- 维护了表级行数计数器，不带 WHERE 的 `COUNT(*)` 直接返回，不扫表。
- 崩溃后不易恢复，生产业务表基本不再使用。

## 三、InnoDB 与 MyISAM 对比

| 对比项 | InnoDB | MyISAM |
| ---- | ---- | ---- |
| 事务 / 崩溃恢复 | 支持 | 不支持 |
| 锁粒度 | 行级锁 | 表级锁 |
| 外键 | 支持 | 不支持 |
| MVCC | 支持 | 不支持 |
| 索引结构 | 聚簇索引，数据和索引一体 | 非聚簇，索引与数据分离 |
| COUNT(*) 无条件 | 扫描统计 | 直接读计数器 |
| 适用场景 | 需要事务、高并发读写（默认选择） | 以读为主的归档/日志类场景 |

> 另有 Memory 引擎：数据全在内存、默认哈希索引、重启后数据丢失，适合临时表。
