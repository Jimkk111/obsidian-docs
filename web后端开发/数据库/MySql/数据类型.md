# 数据类型

MySQL 数据类型分为数值、字符串、日期时间三大类（官方手册第 11 章 Data Types）。建表时为字段选择合适的类型，原则：**够用的前提下尽量小、尽量确定**。

## 一、数值类型

### 1. 整数类型

| 类型 | 字节 | 有符号范围 | 无符号范围（UNSIGNED） |
| ---- | ---- | ---- | ---- |
| TINYINT | 1 | -128 ~ 127 | 0 ~ 255 |
| SMALLINT | 2 | -32768 ~ 32767 | 0 ~ 65535 |
| MEDIUMINT | 3 | 约 ±838万 | 0 ~ 16777215 |
| INT / INTEGER | 4 | 约 ±21.4亿 | 0 ~ 约 42.9亿 |
| BIGINT | 8 | 约 ±9.2×10^18 | 0 ~ 约 1.8×10^19 |

- 加 `UNSIGNED` 表示无符号（只存非负数），范围扩大一倍。
- 整数后的显示宽度（如 `INT(11)`）只影响零填充显示、不影响取值范围，8.0.17 起已废弃，不要与字节数混淆。

### 2. 小数类型

| 类型 | 说明 |
| ---- | ---- |
| FLOAT | 4 字节，单精度浮点数，**近似值**，存在精度丢失 |
| DOUBLE | 8 字节，双精度浮点数，**近似值** |
| DECIMAL(M,D) / NUMERIC(M,D) | **精确小数**，M 总位数（默认10，最大65），D 小数位数（默认0，最大30） |

涉及金额、需要精确计算的场景（如 `price DECIMAL(10,2)`）必须用 DECIMAL。

## 二、字符串类型

| 类型 | 说明 |
| ---- | ---- |
| CHAR(M) | 定长，M 为 0~255 字符，不足 M 右侧补空格；存取效率高 |
| VARCHAR(M) | 变长，M 为 0~65535 字节（受行大小 65535 字节限制），额外 1~2 字节记录长度；节省空间 |
| TINYTEXT / TEXT / MEDIUMTEXT / LONGTEXT | 文本数据，上限分别约 255B / 64KB / 16MB / 4GB |
| BINARY(M) / VARBINARY(M) | 二进制字符串 |
| TINYBLOB / BLOB / MEDIUMBLOB / LONGBLOB | 二进制大对象（图片、文件等，一般不建议入库） |
| ENUM('v1','v2',...) | 单选枚举，最多 65535 个成员 |
| SET('v1','v2',...) | 多选集合，最多 64 个成员 |

CHAR 与 VARCHAR 的选择：长度固定（身份证号、手机号、性别）用 CHAR；长度不定（用户名、邮箱、地址）用 VARCHAR。

## 三、日期时间类型

| 类型 | 字节 | 格式 | 范围 |
| ---- | ---- | ---- | ---- |
| YEAR | 1 | YYYY | 1901 ~ 2155 |
| DATE | 3 | YYYY-MM-DD | 1000-01-01 ~ 9999-12-31 |
| TIME | 3 | HH:MM:SS | -838:59:59 ~ 838:59:59 |
| DATETIME | 8 | YYYY-MM-DD HH:MM:SS | 1000-01-01 00:00:00 ~ 9999-12-31 23:59:59 |
| TIMESTAMP | 4 | YYYY-MM-DD HH:MM:SS | 1970-01-01 00:00:01 UTC ~ 2038-01-19 03:14:07 UTC |

DATETIME 与 TIMESTAMP 的区别：

- 存储空间：8 字节 vs 4 字节，TIMESTAMP 范围小（存在 2038 问题）。
- **时区**：TIMESTAMP 存储时自动转换为 UTC、读取时按当前时区转换，会随时区变化；DATETIME 存什么读什么，与时区无关。

## 四、选择建议

优先选用小的、能覆盖业务范围的类型；能用数值类型就不用字符串；避免 NULL（可设 NOT NULL + DEFAULT，减少比较与索引代价）；日期用 DATETIME/TIMESTAMP 而非字符串存储。
